# 本地文件模型重构：下载 / 曲库 / 缓存 / 本地歌单（设计）

**日期：** 2026-10-14
**状态：** 待评审
**取代：** `2026-10-13-local-library-design.md` 里「下载目录同时当曲库扫」与「`↓` 按文件名认」两条；
其余（合成 mid、索引放缓存目录、免登录可达）继续有效。

## 背景与目标

这一轮的起因是使用者的原话：

> 既有曲库又有本地下载，这两个设计好像有点不行……调整播放 QQ 歌曲的本地优先策略，不再使用曲库中
> 的歌曲作为命中的元素。

先把**今天的事实**核清（这是设计的地基，四条都可对着代码验）：

1. **QQ 歌的本地命中链只有两跳**：缓存（按 mid）→ 下载目录（按 `歌手 - 标题` 扫出来的文件名表）
   —— `state.rs:1365 local_source` → `player.rs:89-113 local_copy`。**曲库索引一次都没参与**；
   它只喂第 5 屏（`state.rs:898,1623`）与被本地歌单拿来按 mid 补字段（`state.rs:2295`）。
   它「看起来参与」，是因为默认 `[library] dirs` = `download_dir`，同一个目录被扫了两遍。
2. **三条判定精确度不一**：`●` 缓存按 mid，精确（`cache.rs:35-56` 与文件名解析
   `cache.rs:102-127`）；`↓` 按 `download::file_stem` = `歌手 - 标题` 猜（`download.rs:142-152`,
   `rows.rs:382-388`）；「已在曲库」这条判定**不存在**。
3. **同一份字节两个答案**：曲库屏里那份文件永远不亮 `↓`（`rows.rs:367,395-402` 对
   `Source::Local` 恒 `downloaded: false`），而它在在线列表里亮（按文件名）；播放条标签取决于
   「你从哪屏进来」（`PlaySource::{Download, Library}`），README 自己写着「同一份文件从 `5` 那屏
   播写『曲库』、从在线列表里播写『下载』」。
4. **「我下过哪些歌」没有持久记录**：`downloads` 是每次启动重扫目录得到的内存表
   （`state.rs:832,911-913`）；曲库索引条目也没有 mid 字段（`library.rs:29-38`）。

**目标**：让「本地有这份吗」变成一个**按 mid 查表**的精确问题，让「这份文件哪来的」有一个
**统一的答案**，并顺手把三个目录的职责分开——下载目录归 canto 管、曲库目录归使用者管、缓存归
「听过就丢」。

**成功标准**（真机可验，tuios 那层）：

- 下载一首后：下载目录里出现音频 + 同名 `.lrc` + `downloads.json` 一条带 mid 的记录；在线列表
  那一行的 `↓` 立刻亮（不再依赖文件名）。
- 把那个音频改名（保留索引）：`↓` 灭，第 5 屏对应条目消失（幽灵条目被校验掉）。
- 把整个 `downloads.json` 删掉：第 5 屏的下载歌一并消失（未登记文件不认，见决策 11）。
- `[library] dirs` 指向一个真实目录：第 5 屏同时列出「下载」与「目录」两种来源，**无重复**；
  把 `download_dir` 也写进 `dirs` 仍然无重复（扫描跳过它）。
- 未登录（或断网）：第 5 屏里下载歌的标题 / 歌手 / 专辑 / 时长来自索引，歌词来自同目录 `.lrc`，
  `--log debug` 里零 HTTP。
- 播放条那一格：同一份下载的歌，从在线列表播与从第 5 屏播都写「下载」。
- 把 `[cache] mb` 临时调小让超限：`sweep` 只删音频，`.lrc` 与 `library.json` 一个不动。

## 非目标（YAGNI，明确不做）

- **不做内容哈希**：本地身份仍是 `local:<绝对路径>`（改名 = 另一首），这是既有取舍，继续。
- **不做目录监听**（`inotify`/`ReadDirectoryChangesW`）：仍是启动扫 + `r` 重扫。
- **不做「未登记文件」的自愈**：下载目录只认索引（决策 11）。
- **不迁移既有下载文件**：升级后它们没有 mid 登记，不进任何索引（使用者会清空后重测）。
- **不做「按 tag 把曲库文件匹配成某首 QQ 歌」**：跨世界匹配只能靠猜，这轮就是要砍掉猜。
- **不多下载目录**（一个 `download_dir`）、**不给缓存写索引文件**（决策 5）。
- 不做本地歌单的多文件 / 手动排序 / 导入导出。

## 决策记录

| 决定 | 取值 | 为什么 |
|---|---|---|
| 曲库是否参与 QQ 歌取源 | **不参与**：缓存 → 下载 → 线上 | 曲库是「使用者自己的文件」的世界；跨世界匹配只能靠猜（今天也只是靠同名文件撞上） |
| 「本地有这份吗」的判据 | **两个都按 mid**：缓存从文件名读、下载从索引读 | 判定与身份分离；`↓` 不再认错同歌手同标题 |
| 下载索引文件位置 | **`<download_dir>/downloads.json`**（使用者定） | 整个目录搬走 / 备份 / 同步时登记跟着走 |
| 索引字段 | **与缓存侧对齐**（同一个内存结构 `LocalTrack`），下载侧补离线显示要的字段 | 使用者定的「字段尽量一致，必要时补充」 |
| 缓存是否也写索引文件 | **不写** | 缓存那份的 mid / 档位就在文件名里（`<mid>.<档位>.<ext>`），再写一份只会多一份会与目录不一致的状态 |
| 界面身份 | **一律 `local:<路径>`**（下载歌也是） | 使用者定的：mid 只服务「在线歌的本地优先」与在线列表的 `↓`；本地歌单因此只有一种条目 |
| 歌词放哪 | **与音频同目录**（下载目录内、缓存目录内各自同目录），`[paths] lyrics_dir` 删掉 | 使用者定的：不再单独一个歌词目录 |
| `[library] dirs` 语义 | **两态**：不写 / `[]` = 不扫别人的目录（第 5 屏只列下载歌）；列表 = 再加上这些 | 扫描跳过下载目录后，「不写 = 扫 download_dir」已经等于什么都不扫；「本地功能整体关掉」随之取消 |
| 第 5 屏形态 | **合并列表**：下载 ∪ 曲库目录，加一列 `来源`（`下载` / `目录`） | 使用者定的；同一份文件只出现在一个索引里（按路径去重） |
| 播放条来源标签 | **按数据**：这份文件在下载索引里 → `下载`；只在曲库索引里 → `曲库` | 同一份字节无论从哪屏播都同一个答案（今天按入口，README 自己认了这条限制） |
| 未登记文件 | **不认**：下载目录里没登记的音频不显示、不参与任何判定 | 使用者定「不管它们」；下载目录从此是 canto 管的目录，自己的文件放曲库目录 |
| 索引 / 目录不一致 | **文件为准**：启动逐条校验（存在 + 大小），幽灵条目丢掉、大小不符以磁盘为准 | 索引是登记册，真相永远在磁盘上 |
| `cache::sweep` 的范围 | **只认音频形态**（`<mid>.<档位>.<ext>`）：`.lrc`、`library.json`、子目录都不计入上限也不删 | 顺手修掉一个老坑：今天它把目录里所有文件都算进去（`cache.rs:146-187`），`library.json` 超限时会被当缓存删掉（能重扫所以没人发现）；歌词压平后这条必须改 |

## 1. 术语与三个索引

| 名字 | 位置 | 管什么 | 界面身份 | 谁写 |
|---|---|---|---|---|
| **播放缓存** | `~/.cache/canto`（**无索引文件**） | `<mid>.<档位>.<ext>` + 同目录 `<mid>.lrc` / `<mid>.trans.lrc` | mid（在文件名里） | 播放 / 听完转正 / 取歌词 |
| **下载** | 音频与歌词在 `<download_dir>`；登记在 **`<download_dir>/downloads.json`** | `mid ↔ 文件` + 离线显示字段 | `local:<路径>` | 下载成功时写一条 |
| **曲库** | `~/.cache/canto/library.json`（不变） | 扫 `[library] dirs` 的音频（**跳过下载目录**）+ 同 stem 的 `.lrc` | `local:<路径>` | 重扫时 |
| **本地歌单** | `~/.config/canto/local_playlists.json`（不变，**一份**） | 使用者自己组织的列表（路径身份 + 快照） | `local:<路径>` | 建 / 改名 / 加 / 移出 / 删 |

「同一份文件只属于一个索引」是硬约束：曲库扫描跳过下载目录（决策 8），所以第 5 屏的合并列表
不会出现重复行。

## 2. 取源链与三条判定

**取源链（QQ 歌）**：`缓存(mid)` → `下载(mid)` → 线上。本地歌（`Song.path()` 有值）仍走自己的
路径，不经过这条链。

| 判定 | 键 | 数据源 |
|---|---|---|
| `●` 已缓存 | mid | 缓存目录的文件名 + 元数据（`cache::cached_entries`） |
| `↓` 已下载 | mid | `downloads.json`（启动校验过的那一份） |
| 在第 5 屏里 | 路径 | 合并列表（下载 ∪ 曲库） |

mid 的作用被限定成两件事：**在线歌起播前的本地优先判定**、**在线列表里标 `↓`**。

## 3. 索引文件字段

### 3.1 `<download_dir>/downloads.json`（新增）

```jsonc
{ "version": 1,
  "tracks": [{
    "mid": "0039MnYb0qxYhV",        // 唯一键：只用于本地优先判定与 `↓`
    "file": "许嵩 - 山水之间.flac",   // 相对本文件的名字（而不是绝对路径：目录整体搬走仍然有效）
    "quality": "flac",              // 下载时那份的档位（与缓存侧同款字段）
    "container": "FLAC",            // 扩展名推到的那一格（列表「音质」列）
    "bytes": 28474820,              // 校验用；不符就以磁盘为准更新
    "title": "山水之间", "singers": "许嵩", "album": "不如吃茶去",
    "duration_secs": 251,           // 这四个：不登录 / 没网时列表也要写得出名字与时长
    "at": 1760000000                // 下载时间（排序用）
  }] }
```

- 读：文件缺失 / 坏了 / 版本不符 → **空索引**（跟本地歌单一个口径：宁可当没有，也不要带着半份
  数据接着写），给一句状态行通知、细节进日志。
- 校验：逐条检查 `file` 在不在、`bytes` 对不对；不在 → 丢这条；大小不符 → 以磁盘为准更新。
- 写：临时文件 + rename（跟历史 / 本地歌单一个套路）；**只在界面线程写**——下载在后台线程跑完
  只回一个 `Saved`，`poll_transfer` 收到那条消息时再 upsert，跟今天 `refresh_downloads` 的时机
  一致（索引不需要锁）。
- 与缓存侧共用一个内存结构，字段对照：

| 字段 | 缓存那份 | 下载那份 |
|---|---|---|
| `mid` | 文件名里 | 索引 |
| `path` | 拼出来（目录 + 文件名） | 索引（`file` + 目录） |
| `quality` | 文件名里的档位 | 索引（下载时知道） |
| `container` | 扩展名 | 索引（可随时用扩展名重算） |
| `bytes` | 现读 metadata | 现读 metadata（索引里的值只用于校验） |
| `title` / `singers` / `album` / `duration_secs` | 空（列表本来就有接口数据） | 索引（离线显示） |
| `at` | 文件 mtime | 索引 |

### 3.2 `~/.cache/canto/library.json`（版本 +1）

```jsonc
{ "version": 2, "dirs": ["D:/music"],
  "entries": [{
    "path": "D:/music/专辑/一曲.flac",
    "mtime": 1760000000, "size": 28474820,
    "title": "一曲", "artist": "某人", "album": "专辑", "duration_secs": 251,
    "lyric": "D:/music/专辑/一曲.lrc"    // 新增：同目录同名 .lrc，没有则 null
  }] }
```

- 字段变了就 +1、整份丢弃重扫（`library.rs` 本来的约定），不做迁移。
- 扫描时把 `.lrc` / `.trans.lrc` 与同 stem 的音频配对；`.lrc` **既不计入音频、也不算「不支持的
  音频」**（今天会静默跳过，`library.rs:70-81`）。内嵌歌词仍靠 `lofty` 在播放时读，不落索引。
- 扫描**跳过下载目录**：`dirs` 里正好是它 → 那一条不扫；`dirs` 里是它的**父目录**（例如
  `download_dir = D:/music/canto`、`dirs = ['D:/music']`）→ 递归到它时整棵子树跳过。两种嵌套都
  要成立，否则同一个文件会在两个索引里各出现一次。

### 3.3 `~/.config/canto/local_playlists.json`（结构不变，快照补两个字段）

```jsonc
{ "version": 2,
  "playlists": [{ "name": "通勤",
                  "songs": [{ "mid": "local:D:/music/一曲.flac",
                              "title": "一曲", "singers": "某人",
                              "album": "专辑", "duration_secs": 251 }] }] }
```

补 `album` / `duration_secs`：歌单里那两列今天恒为 `—` / `--:--`（design.md 记的欠账②），快照
里加两个字段就还掉了。版本 +1，老文件按空处理（既有约定）。

## 4. 目录布局与命名

```
<download_dir>/
  许嵩 - 山水之间.flac          # 音频（`歌手 - 标题.<扩展名>`，非法字符换 `_`）
  许嵩 - 山水之间.lrc           # 下载时另存的歌词（同 stem，与音频同目录）
  许嵩 - 山水之间.trans.lrc     # 翻译歌词（同上）
  downloads.json               # 下载索引（新增）

~/.cache/canto/
  <mid>.<档位>.<ext>           # 播放缓存（名字里就带着 mid 与档位）
  <mid>.lrc / <mid>.trans.lrc  # 歌词缓存（**不再放 lyrics/ 子目录**）
  library.json                 # 曲库索引
```

- 下载歌词：`download::save` 不再接 `lyrics_dir`，写进音频同目录（`write_lyrics(stem, dir, …)`）。
- 缓存歌词：`cache::lyric_dir()` 返回缓存根目录本身；`<mid>.lrc` / `<mid>.trans.lrc` 天然不会被
  `cached_entries_in` 认成歌（`rsplitn(3,'.')` 时档位位解析不出来），但**必须**保证 `sweep` 不碰
  它们（见决策 13）。
- `sweep` 顺手清掉老版本的 `<cache>/lyrics/` 子目录（一句话进日志）——它已经不再被读，留着只是
  永久占地方。
- 任何扫目录的地方都要忽略非音频（`.lrc` / `.json`）：曲库扫描靠扩展名白名单已经如此；下载目录
  整目录被曲库跳过。

## 5. 配置面变化

```toml
[paths]
# 下载目录（`d` 键落盘的歌曲、同目录的歌词、以及下载索引 downloads.json 都放这儿），支持 `~`
download_dir = '/Users/you/Music/canto'

[cache]
# 播放缓存上限（MB，0 = 关掉）；缓存在 ~/.cache/canto（音频与歌词同目录）
mb = 1024

[library]
# 本地曲库额外扫哪些目录（第 5 屏；`r` 重扫）。**下载目录会被自动跳过**（那批歌由下载索引管）：
#   不写 / dirs = []     → 不扫别人的目录（第 5 屏只列已下载的歌）
#   dirs = ['D:/music']  → 再加上这些目录里的文件（相对路径按启动时的工作目录算）
# dirs = ['D:/music', 'E:/flac']
```

- `[paths] lyrics_dir` 删除（`canto config init` 生成的模板不再有它；老配置里残留的它会被当成
  「不认识的键」点名进日志）。
- `[library] dirs` 从三态变两态，模板里那三种写法的注释重写（旧注释里「本地功能整体关掉」那句
  要删）。
- 段名 `[paths]` 保留（只有一个键，但改回顶层要再动一轮刚改完的模板，不值）。

## 6. 界面

- **第 5 屏 = 合并列表**：下载条目（来自索引）+ 曲库条目（来自扫描），排序沿用同一把尺
  **歌手 → 专辑 → 标题**（下载条目的专辑来自索引，缺就是空串）。屏名保持「本地曲库」，来源由列
  区分（改名会牵动 README / 冒烟等待串，不值）。
- **新列 `来源`**：`下载` / `目录`，宽 4（跟今天那两个标记列同宽），进让位顺序（窄屏先撤）。
  `local_columns()` 今天刻意不画 `缓存` / `下载` 两列（`rows.rs:162-172`），这一列正好顶上。
- **`●` / `↓`（在线列表与历史屏）**：`●` 不变（按 mid）；`↓` 改查下载索引的 mid，**不再按文件名**。
- **播放条来源标签**：`在线` / `缓存` / `下载`（这份文件在下载索引里）/ `曲库`（只在曲库索引里）。
  判定从「哪条链路进来的」改成「查这两个索引」。
- **`d` 下载**：先查下载索引——同一 mid 已有条目且文件在 → 直接报「已下载：<文件名>」（今天靠
  `<stem>.<ext>` 存在与否猜）；文件不在 → 重下并覆盖那条记录。
- **`r` 重扫（第 5 屏）**：重扫曲库 + 重载并校验下载索引；下载完成后同样重建合并列表。
- **首页两格与第 5/6 屏不再有「本地功能关掉」这个状态**（`local_features_on()` 及那句
  「本地功能已关闭：config.toml 的 [library] dirs 是空的」一起删）。

## 7. 行为细节与边界

| 情形 | 行为 |
|---|---|
| 两个不同 mid 的文件名撞车（同歌手同标题） | 下载时给文件名加序号（`… (2).flac`）；同一 mid 重复下载仍走「已下载」那条路（今天会互相冒充成已下载） |
| 索引里的文件被改名 / 挪走 | 启动校验时丢掉那条（`↓` 灭、第 5 屏消失）；`downloads.json` 不会自动跟着改 |
| 索引里的文件被换掉（同名不同内容） | 大小不符 → 以磁盘为准更新 `bytes`，`quality` 保留（我们只承诺「这份文件是这首」） |
| `download_dir` 改了 | 新目录没有 `downloads.json` → 下载歌全部消失；旧目录的索引还在（要一起搬）。写进 README / 模板注释 |
| 索引文件坏了 / 版本不符 | 空索引 + 状态行一句 + 日志细节；屏 5 只剩曲库那半边 |
| 曲库目录里手放了音频 | 照旧进曲库索引（来源 `目录`），有自己的歌词就配上 |
| 下载目录里手放了音频 | **不认**（未登记）——写进 README 已知限制 |
| 播放中途文件被删 | 与今天一致：起播失败，状态行报错 |
| 历史 / `♪` 的身份 | 从第 5 屏播下载歌 → `local:<路径>`；从在线列表播同一首 → QQ mid。两者在界面上仍是两首（使用者选了路径身份，记为已知限制） |
| 歌词 | 本地一律「同目录同名 `.lrc` → 内嵌 tag」两段（`library::local_lyric` 少一段）；缓存那半边（`<mid>.lrc`）不变 |

## 8. 要删 / 要改的旧代码（不吃兼容）

- `config`：`[paths] lyrics_dir`；`LibraryConfig.dirs` 从 `Option<Vec<String>>` 简化成
  `Vec<String>`（两态之后「不写」与「空表」同义，那个 `Option` 的三态语义没有用武之地了）。
- `download`：`scan_downloads()`、`Downloaded`、`save(…, lyrics_dir, …)` 的那个参数（换
  `DownloadIndex`）。
- `library`：`local_lyric(path, lyrics_dir)` 的第二段；`INDEX_VERSION` 1 → 2。
- `cache`：`lyric_dir()` 指向缓存根；`sweep_dir` 的白名单；顺手清老 `lyrics/` 子目录。
- `state`：`local_features_on()` 与「本地功能已关闭…」提示；`downloads` 字段从
  `HashMap<stem, Downloaded>` 换成下载索引（按 mid 查 + 按路径反查）。
- `rows`：`Field::Downloaded` 的取值改按 mid；新增 `Field::Source`。

## 9. 测试计划

**第一层（`cargo test`：纯函数 + `TestBackend` + 哑引擎）**

- 下载索引：缺失 / 坏 / 版本不符 → 空；`upsert`（同 mid 覆盖、同名不同 mid 加序号）；校验
  （幽灵条目丢弃、大小不符更新）；`save` 往返（tmp + rename）。
- 曲库扫描：`.lrc` / `.trans.lrc` 与音频配对；`.lrc` 不计入「不支持的音频」；跳过下载目录（含子
  目录）；隐藏目录照旧跳过。
- 曲库索引：版本 2 往返；版本不符按空重扫。
- `cache`：压平后 `cached_entries_in` 不把 `<mid>.lrc` / `<mid>.trans.lrc` 当歌；`sweep_dir` 只删
  音频形态、`.lrc` 与 `library.json` 与子目录不动。
- `local_copy`：QQ 歌按 缓存(mid) → 下载索引(mid) → `None`；本地歌走自身路径；标签按「路径在不在
  下载索引里」定（同一份文件从任何入口进都是 `下载`）。
- 列表：`local_columns()` 在 60 列下的让位结果（`来源` 列在不在）；行里来源值。
- 状态机：合并列表（下载 ∪ 曲库、无重复、排序）；`r` 重扫后仍无重复；`↓` 按 mid（同歌手同标题
  不再互相标）；`d` 命中索引不重下；索引条目对应文件被删后该条消失。
- 配置：`[paths]` 只认 `download_dir`（`lyrics_dir` → 未知键点名）；`[library] dirs` 两态；模板
  注释与三种写法一致（模板回读 == 默认值那条继续当钉子）。

**第二层（tuios 真机，按 AGENTS 的窗口冒烟）**

- 清空下载目录 → 下载一首：目录里音频 + `.lrc` + `downloads.json`；在线列表 `↓` 立刻亮；第 5 屏
  出现「下载」来源那一条；重启仍是同一状态。
- 改名音频 → `↓` 灭、屏 5 那条消失；删 `downloads.json` → 屏 5 的下载歌消失。
- 配 `dirs` 指向真实目录 → 两种来源混排、无重复；把 `download_dir` 也写进 `dirs` 仍无重复。
- 未登录：屏 5 下载歌的标题 / 时长来自索引、歌词来自同目录 `.lrc`；`--log debug` 零 HTTP。
- `[cache] mb` 调小让超限：只删音频，`library.json` 与 `.lrc` 还在。

## 10. 影响面与欠账

要改的文件：`config.rs`、`download.rs`、`library.rs`、`cache.rs`、`player.rs`、
`tui/state.rs`、`tui/draw/{rows,content}.rs`、`playlists.rs`、`README.md`、`docs/design.md`。

本 spec 不解决、明确记下的欠账：

- 历史 / `♪` 的身份割裂（路径 vs mid）仍在（使用者选了路径身份）。
- 换 `download_dir` 要连 `downloads.json` 一起搬。

- 第 5 屏的名称仍叫「本地曲库」（现在含下载歌），改名留给以后一起做。
