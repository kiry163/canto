# canto

自用的 QQ 音乐播放器（Rust）。**所有功能都在终端界面里**——登录、歌单、播放、歌词、搜索、下载、播放历史。

## 进度

| 能力 | 状态 |
|---|---|
| 登录：界面内扫码（二维码画在终端里）/ 粘贴 cookie | ✅ |
| 我的收藏 / 我的歌单（含音质档位） | ✅ |
| 播放：vkey 取流 → 边下边解码出声 | ✅ |
| 显式队列：追加 / 插队 / 删除 / 清空 / 跳播 + 四种播放模式 | ✅ |
| 播放历史（落盘、可重播、可清空） | ✅ |
| 歌词（行级 + 翻译，跟随播放高亮） | ✅ |
| 搜索（独立一屏，不顶掉正在看的歌单） | ✅ |
| 下载（歌曲 + 同名歌词） | ✅ |
| 歌单写入：收藏 / 加进歌单 / 从歌单移除 | ✅（「取消收藏」见「已知限制」） |
| 配置文件 `config.toml`（音质下限 / 下载目录 / 历史上限） | ✅ |

## 用法

```bash
cargo run                 # 进界面（默认命令，也是唯一的命令）
cargo run -- --log info   # 把播放细节写进日志文件
cargo run -- --help       # 只有 --log / --version
```

首次运行会生成 `config.toml`；没有有效会话时界面先出登录屏（下图右边那个二维码要
**≥112 列 × 61 行**的终端，装不下会告诉你需要多大，并给 `c`（粘贴 cookie）与
`o`（用系统查看器打开二维码图片）两条路）。

```

            │                昨夜同门云集                   │

            └──────────────────────────────────────────────┘
┌ 播放 ─────────────────────────────────────────────────────────┐

 Enter 播放 · Space 暂停 · n/b 切歌 · f 收藏 · p 加歌单 · ? 帮助 │ 已插队《晴天》
```

窗**口小于 100 列时菜单收成顶部一行页签**（`1 ♥ 我的收藏 · 2 ≡ 我的歌单 · …`），
主区吃满全宽；小于 60×15 只显示一行「终端太小」。

| 键 | 作用 |
|---|---|
| `1`–`4` | 直达菜单项（我的收藏 / 我的歌单 / 搜索 / 历史） |
| `Tab` | 焦点循环：菜单 → 主区 → 歌词 |
| `j` `k` / `↑` `↓` | 移动选择（焦点在菜单上就是换菜单项） |
| `g` `G` / `Home` `End` | 首 / 尾 |
| `PgUp` `PgDn`（`Ctrl+U` `Ctrl+D`） | 翻页 |
| `Enter` | 歌单列表 = 进入曲目；曲目列表 = 以此列表开新队列并从该首播 |
| `Esc` / `Backspace` | 返回上级 / 取消输入 / 关浮层 |
| `Space` | 播放 / 暂停 |
| `n` / `b` | 下一首 / 上一首（按当前模式走） |
| `←` `→`（`h` `l`） | 后退 / 前进 10 秒 |
| `+` `-`（`,` `.`） | 音量 ±5% |
| `m` | 播放模式：顺序 → 列表循环 → 单曲 → 随机 |
| `a` / `A` | 追加到队尾 / 插到下一首 |
| `u` | 队列浮层（`Enter` 跳播 · `d` 删除 · `Shift+D` 清空） |
| `p` | 把选中曲目加进某个歌单 |
| `x` | 从当前歌单移除选中曲目（「我喜欢」见「已知限制」） |
| `f` | 收藏选中曲目（写进「我喜欢」） |
| `d` | 下载选中曲目（含同名歌词） |
| `y` | 歌词块开 / 关 |
| `/` | 跳到搜索屏并聚焦输入框 |
| `?`（或 `F1`） | 帮助浮层（按当前屏列出可用键；里面有 `L` 登出） |
| `q` / `Ctrl-C` | 退出 |

**队列语义**：`Enter` 那一刻的列表成为队列（换歌单、重新搜索都不影响它），之后
`a`/`A` 往队列里加，`u` 里能跳播、删除、清空。一首播完按模式决定下一首；顺序模式
播到队尾会停下并在状态行说明。队列里没版权的歌（实测常见）会自动跳过，连着 3 首都
不可播就停下报错。**队列内容与各屏选中位置退出即丢**（不落盘）。

日志写文件：`~/Library/Application Support/canto/canto.log`——屏幕归界面，往
stdout/stderr 打印会糊屏；`cargo run -- --log info` 可以把播放细节记进去。

## 配置

`~/Library/Application Support/canto/config.toml`（首次运行自动生成）：

```toml
# 音质下限：从这一档往下找 —— hires | flac | 320 | 128
quality = "flac"
# 下载目录（`d` 键落盘的地方），支持 `~`
download_dir = "/Users/you/Music/canto"
# 播放历史最多保留多少条
history_limit = 500
```

字段缺了就用默认值；**整个文件写坏了也能启动**（用默认值，并把解析错误显示在状态行）。
界面上不提供设置项——改配置就是开这个文件改，改完重启。

## 音质档位（实测，2026-10-09）

同一首歌在 CDN 上有一组候选文件。`canto` 按「立体声优先、音质降级」排队，逐个**真去开**，
第一个能解码的胜出——因为服务端对不存在/无版权的文件**也会**返回 `purl` + `vkey`，
只有真去取才 404（`file not exist`），光看接口结果判断不出来。

| 前缀 | 实测规格 | 体积（4 分钟量级） | 用途 |
|---|---|---|---|
| `AI00` | flac 192kHz/24bit 立体声 | ~150MB | 母带，仅 `quality = "hires"` |
| `F000` | flac 44.1k/16bit 立体声（个别 48k/24bit） | ~25MB | **默认首选** |
| `Q000` | flac 44.1k/16bit 立体声 | ~25MB | 默认次选 |
| `M800` | mp3 320k 立体声 | ~9MB | 无损不可用时 |
| `M500` | mp3 128k 立体声 | ~3.5MB | 兜底 |
| `Q001` | flac 44.1k/16bit **6 声道** | ~62MB | 5.1 环绕，排在 mp3 之后 |
| `O801` | vorbis 44.1k **4 声道** | ~19MB | 环绕，最后兜底 |

`quality` 的语义是「从这一档往下找」：`hires`（母带）→ `flac`（默认）→ `320` → `128`。
环绕声版本排在立体声之后，是因为它们只会经过 rodio 的降混，白白多花带宽。

## 已知限制

- **「取消收藏」接口走不通**：收藏能写进去，但把歌**从「我喜欢」移出**恒回 `80105`
  （`DelSonglist` + `dirId=201`，换 `tid`、换 `songType`、换 `tid=0` 都一样），
  暂时只能去官方客户端取消收藏。普通歌单的加/删都正常。
- 经典写入接口 `fcg_music_add2songdir.fcg` 现在对任何会话都回 `{"code":403,"title":"no permit"}`
  ——**与登录方式无关**（扫码会话照样拒绝），`g_tk=5381` 与按各 cookie 算的 hash33 都不行。
  写歌单走 `musicu.fcg` 的 `music.musicasset.PlaylistDetailWrite`（见 `qq/write.rs`）。
- 搜索接口不返回 hires 大小，所以搜索结果的音质标签和体积可能低估（不影响取流，候选链是固定的）。
- 列表里那个体积来自**接口元数据**，播放条里那个来自**实际取到那份流**的 `Content-Length`：
  想知道真在下多大，看播放条。
- **历史屏的行不显示时长与档位**：历史里只存 mid / 标题 / 歌手（够重播：取流只认 mid），
  没有的字段就不画，免得显示成假的 `00:00`。
- **同一首歌在同一列表里出现两次，两行都会标 `♪`**：标记按 mid（QQ 全局唯一）比对，
  比按「标题 — 歌手」字符串准，但重复出现的同一首无法区分。
- 「会话已失效」的判定码（`session::looks_expired`）按 401 与已知文案写就，
  **还没等来一次真实的会话过期去核对**；下次遇到时把 `--log debug` 里的响应补进去收紧。
- 下载的 `hires` 档位体积很大（单曲约 150MB），默认仍是「立体声无损优先」。

## 设计要点

**界面**

- 界面分三块：**左侧菜单**（我在哪）+ **主区**（这里有什么）+ 底部歌词，播放条与状态行
  常驻。每个菜单项各存一份列表与选中位置，所以「搜一下歌单就没了」不会发生。
- **键位映射是纯函数**（`tui/keys.rs`）：`KeyEvent` + 上下文 → `Action`，模态（帮助 /
  队列浮层 / 选择框）优先，输入态其次。这类优先级靠手点很难验证，所以用单测钉住。
- **队列也是纯逻辑**（`tui/queue.rs`）：四种模式的推进、增删插的边界都在那里单测；
  「一首播完往哪走」与「按 `n` 往哪走」是两个入口（单曲循环下按 `n` 仍要前进）。
- 状态行**分成两段**：左边永远是当前焦点的键位提示，右边才是一次性状态（加载 / 错误 /
  结果）。旧界面把两者挤在同一行，加载中就看不到键位提示。
- 列宽按**显示宽度**算而不是字符个数：中文与书名号是双宽字符，按字符数留列会把尾巴裁掉
  （实测「已加载《嗯》」6 个字符占 9 列）。
- 歌词块只在「正在放 + 有歌词 + 面板开着」时占位（`clamp(主区/3, 5, 12)` 行），不播放时
  不画空框、矮屏自动关掉。

**数据链路**

- **域名感知的 cookie jar**（`cookie_store`），不是扁平 map。QQ 服务端会用
  `Set-Cookie: p_skey=` 明确清掉某个**域**上的旧凭据，扁平存储会把别的域的同名
  cookie 一起覆盖——voicefox 的扫码换 code 就栽在这上面。请求头由 reqwest 按 URL 自动拼。
- 粘贴来的 cookie 统一挂 `.qq.com` 并给 30 天过期时间。不这样做它只是**会话 cookie**，
  序列化时会被静默跳过，登录跨不了进程；`session.rs` 里有测试钉住这条。
- 扫码登录的每一跳都靠会话 jar 自动收 `Set-Cookie`；跟跳转链用的是**不自动跟随**的
  客户端（`http::client_without_redirect`）——自动跟随时 reqwest 把 302 吃掉，
  `Location` 与中间各跳（`p_skey`/`skey`）的 cookie 全丢，这正是 voicefox 当初
  「扫码成功但拿不到音乐凭证」的结构性原因。
- 所有接口的响应都经过 `qq::read_json`：`Content-Type` 不可信，且**登录失效只在这一个
  地方判定**（`session::looks_expired`），界面按错误类型切回登录屏。
- **边下边播**：`media.rs` 把 HTTP 响应做成 `Read + Seek`（rodio 的解码器要 `Seek`）。
  CDN 支持 `Accept-Ranges: bytes`，所以往回 seek 就重开一次 `Range` 请求，
  往前 seek 就近读掉——正常顺序播放只有一次请求，不落盘。
- 开流时校验**魔数**（`fLaC`/`OggS`/`ID3`/`ftyp`…）：CDN 的 `Content-Type` 不可信
  （实测 FLAC 被标成 `audio/x-ogg`、错误页标成 `audio/mpeg`），错误页正文不该被
  解码器当成音频播出去。
- 歌词走 `musicu.fcg` 的 `PlayLyricInfo`，参数里 **`crypt=0` + `qrc=0`** 时返回的是
  明文 base64 的 LRC（正文 `lyric`、翻译 `trans`）。传 `qrc=1` 会换成 QQ 自己的加密
  QRC（hex 密文），要多一整套解密——行级歌词不需要它。
- 写歌单也走 `musicu.fcg`：`AddSonglist` / `DelSonglist`，参数里 `songId` 必须是
  **数字 id**（mid 不行），「我喜欢」是 `dirId=201`（`tid` 给 0 就行）。实测服务端码：
  `0` 成功（重复加/删同样返回 0，幂等）、`80092` 歌单不存在或无权、`40000` 方法不存在、
  `80105` 拒绝对「我喜欢」做移除。
- `--log` 传裸级别（如 `debug`）时只作用于 canto 自己，其它库保持 `warn`
  ——否则 reqwest/h2 会把每条连接、每个 HTTP/2 帧都打出来，把你的日志淹掉。

## 文件

```
~/Library/Application Support/canto/      # 全部在系统配置目录下的 canto/
  session.json    # cookie jar（= 账号凭据：别提交、别分享）
  config.toml     # 音质下限 / 下载目录 / 历史上限
  history.json    # 播放历史（最近 N 条）
  canto.log       # 日志（--log 控制级别）
  login-qr.png    # 二维码落盘的一份（终端装不下时用 o 打开）
```

## 代码结构

```
src/
  main.rs      启动：日志 → 配置 → 会话 → 界面（只剩这一条路径）
  cli.rs       --log / --version
  paths.rs     所有落盘路径（会话 / 配置 / 历史 / 日志 / 二维码 PNG）
  config.rs    config.toml：载入、默认生成、坏文件回退、`~` 展开
  history.rs   播放历史：落盘、上限截断、连续去重、相对时间文案
  session.rs   登录态：域名感知 cookie jar、完整性校验、落盘、失效判定
  model.rs     Song / Playlist / Quality / Lyric
  media.rs     HTTP 流 → Read + Seek（Range 重连 + 魔数嗅探）
  player.rs    候选档位 → rodio 解码 → 默认音频设备（后台线程 + 状态快照）
  download.rs  下载歌曲与同名歌词（复用 media 的流）
  qr.rs        二维码 PNG → 终端字符块；落盘与系统查看器兜底
  http.rs      HTTP 客户端（UA / 超时 / 挂会话 jar / 不跟随跳转的变体）
  qq/          接口层
    mod.rs     个人歌单、我喜欢、歌单曲目 + 统一的响应读取与失效判定
    vkey.rs    取播放地址与候选档位顺序
    login.rs   扫码登录三跳链路
    lyric.rs   行级歌词（含翻译）
    search.rs  搜索
    write.rs   歌单写入：收藏 / 加歌 / 删歌
    parse.rs   响应 JSON → 模型
  tui/
    mod.rs     事件循环与 Screen 切换
    state.rs   界面状态、消息处理、菜单与视图路由、队列接入
    keys.rs    键位 → 动作（纯函数，带单测）
    queue.rs   队列模型与四种模式（纯逻辑，带单测）
    login.rs   登录屏：二维码、cookie 输入、扫码轮询
    test_support.rs  测试用的 App / Song / Playlist 构造器
    draw/      骨架布局与各面板：menu / content / lyric / player / status / overlay
```
