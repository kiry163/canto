# 内容区的两个栏：歌词栏与频谱区（设计）

**日期：** 2026-10-13
**状态：** 待评审
**取代：** `2026-10-11-tui-redesign-design.md` §10.4「全屏歌词（`Y`）」里关于「模式」与 `Context::LyricFull`
（现名 `Context::NowPlaying`）的决议（见文末「与旧决议的关系」）。

## 背景与目标

今天有一个「全屏正在播放」的**模式**：按 `Y` 进、`Esc` 退，进出时**换一套按键上下文**
（`Context::NowPlaying`：列表看不见，`d`/`p`/`x`/`A`/`Enter` 这些「对选中那首动手」的键一律不接）。
它带来三处别扭：

1. 同一个东西有两个身份——`y` 是「底部歌词块开关」，`Y` 是「另一个模式」，两者不共享语义；
   在全屏里按 `y` 会**偷偷改掉** `show_lyric` 而屏幕上毫无变化，退出全屏才发现底部那块没了。
2. 一个开关管不了「我想看频谱」这个最简单的事：想只看频谱，得接受一套按键被换掉。
3. 没歌词时底部什么都看不到（`lyric.is_some()` 是显示条件的一部分），使用者不知道是「没歌词」
   还是「没在放」。

目标：把「全屏」拆成**内容区里的两个栏**，各自一个开关、互不干扰，没有模式、没有第二个按键上下文。

## 非目标（YAGNI，明确不做）

- 不做「频谱加高 / 缩小」之类的档位（`v` 只有开/关；大小由布局规则决定）。
- 不做歌词栏的位置/比例配置（贴底、比例写死，见 §1）。
- 不做「多首并排」「封面」等新面板。
- `show_lyric` / `show_spectrum` **不落盘**（跟今天 `show_lyric` 一样：每次启动回到默认：
  歌词开、频谱关）。

## 决策记录

| 决定 | 取值 | 为什么 |
|---|---|---|
| 两个开关的耦合 | **互不干扰**（正交） | 歌词默认就是开的，所以「频谱 + 歌词都要」在默认状态按一下 `v` 就得到。反过来若让 `v` 顺手打开歌词，就会把使用者刚做的 `y`（收起歌词）覆盖掉，且按两次 `v` 回不到原状 |
| 频谱区的键 | **`v`**（小写），删掉 `Y` | 大小写在这套键位里不该表示两件无关的事；`s`/`v`/`f` 都空着，`v`（visualizer）最直白 |
| 键位总约定 | **默认小写**；大写只留给「升级型能力」（全屏、清空这类）或小写已被占用 | 使用者提的约定，本次起生效，写进 `docs/design.md` |
| 频谱区与列表 | **互斥**：频谱区开着就替掉列表 | `v` 要的是「大频谱」（占满整个内容区上下的那一下），不是又一条细缝 |
| 换屏时的频谱区 | **收起来**（`switch_menu` / `go_home` 顺手关） | 切屏 = 「我要去那一屏做事」，频谱挡着就白按了；今天全屏也是这个行为，不改 |
| 浮层画在哪 | **内容区整块**（不再只画列表那块） | 频谱区开着时列表是零高，浮层画在列表上会看不见；播放栏与状态行仍然永远露着 |

## 1. 区域语义（后续交流用这套词）

从下到上：**状态栏** → **播放栏** → **内容区**。内容区里三样东西：

| 名字 | 是什么 |
|---|---|
| **列表** | 当前屏的内容（曲目列表 / 搜索 / 歌单 / 首页的四格…）。**内容区一般情况下就是它** |
| **歌词栏** | 内容区**底部**的一条，放当前句歌词（或「暂无歌词」「歌词加载中…」）。**永远在最下面** |
| **频谱区** | 真频谱那些柱子。**与列表互斥**：开着就替掉列表 |

### 合成规则（`v` = 频谱区开/关，`y` = 歌词栏开/关）

| 频谱区 `v` | 歌词栏 `y` | 内容区（自上而下） |
|---|---|---|
| 关 | 关 | 列表（占满） |
| 关 | 开 | 列表 + 歌词栏 |
| 开 | 开 | 频谱区 + 歌词栏 |
| 开 | 关 | 频谱区（吃满整个内容区）← 大频谱 |

一句话：**频谱区与列表互斥；歌词栏永远在内容区最下面。**

### 高度规则

- **内容区** = 窗口高 − 播放栏 4 行 − 状态栏 1 行（跟今天一样）。
- **歌词栏**占位条件：`show_lyric` **且** 有歌在放（`engine.snapshot().phase != Idle`）**且**
  窗口高 ≥ `MIN_LYRIC_HEIGHT`（20，今天就有这条：矮屏里歌词会把主区挤成一两行）。
  高度：`(内容区 / 3).clamp(5, MAX_LYRIC_HEIGHT)`（`MAX_LYRIC_HEIGHT` = 12）——**只有这一套**。
  今天全屏那套「`内容区 / 2` 夹 7..12」不再需要：那时歌词是主内容、要**读**，所以给得多；
  现在它是底部一条，频谱才是要空间的那个（理由仍然是：频谱的高度收益是线性的，歌词的有用
  高度有上限）。大窗口下两套结果一样（210×42 都是歌词 12 / 频谱 25），只在矮窗口下新规则
  把空间让给频谱。
- **频谱区**：`show_spectrum` 时 = 内容区 − 歌词栏（歌词栏不占位时就是整个内容区）。
- **列表**：内容区 − 歌词栏（频谱区关时）。

## 2. 状态与结构

| 位置 | 改动 |
|---|---|
| `App.show_lyric: bool` | 保留，初值 `true`（不变） |
| `App.show_spectrum: bool` | **新增**，初值 `false` |
| `App.now_playing_full: bool` | **删除**（被 `show_spectrum` 取代） |
| `keys::Action::ToggleNowPlaying` | **删除**，换成 `Action::ToggleSpectrum` |
| `keys::Action::ToggleLyric` / `Action::Home` | 不变 |
| `keys::Context::NowPlaying` | **整个删除**（连它的 `resolve` 分支与测试）：列表永远看得见（或替掉它的频谱区就在原地），没有「对选中那首动手」的键该被禁用的场合 |
| `draw::Areas` | **不变**：`content` 仍是「内容区 − 歌词栏」，频谱区就画在它里面（频谱区开着时列表不画——绘制分支跟今天「全屏 / 列表」那条同构） |
| `draw::SPLIT_MIN_HEIGHT` | **删除**：没有「拆不拆」这一步了（歌词栏是一条、频谱区吃剩下的） |

`App::context()`：删掉 `if self.now_playing_full { return Context::NowPlaying }` 那一支——剩下的次序
（帮助浮层 > 队列/选择框 > 输入框 > 首页 > 列表）不变。

## 3. 键位

| 键 | 动作 | 生效范围 |
|---|---|---|
| `y` | `Action::ToggleLyric`（歌词栏开/关） | 首页 + 四屏（`Context::Home` / `Content`）；今天只在 `Content`，本次补上首页 |
| `v` | `Action::ToggleSpectrum`（频谱区开/关） | 同上（两个上下文各绑一次） |
| `Y` | **删除** | 三个上下文里的绑定全部去掉 |

模态浮层（帮助 / 队列 / 选择框）与输入框里**不绑**：跟 `?`/`j`/`k`/`0` 一样的吞键规则——帮助浮层
开着时 `v`/`y` 不抢，搜索框/筛选框里 `y`、`v` 是**打字**。

**帮助表**（`help_rows` 的「全局」段）：补 `y 歌词栏开 / 关` 与 `v 频谱区开 / 关` 两行，删掉原来的
`Y 全屏：歌词 + 频谱`。状态行提示保持 3–5 个最顺手的，**不加** `v`——它进 `?` 查得到。

## 4. 绘制

- **列表**：频谱区关时照今天的 `draw_content` / `draw_home` 画在 `Areas.content` 上。
- **频谱区**：频谱区开时画在 `Areas.content` 上（列表不画）。标题：歌词栏不在时带歌名
  （`频谱 · 歌名`），在时只写「频谱」——跟今天全屏的两条标题规则一致（歌名不能让两块都挂，
  也不能两块都不挂）。没有可画的数据时照旧给 `spectrum_message(phase)`（「缓冲中…」/「未在播放」）。
- **歌词栏**：`Areas.lyric` 上照今天的 `draw_lyric` 画（居中、当前句加亮、翻译、自动滚动都在原地）。
  **新增的只是「没有歌词也画」**：`lyric` 为 `None` 时写「歌词加载中…」（`lyric_loading`）或
  「暂无歌词」——这两句 `lyric.rs` 里现成，今天只是显示条件挡住了、画不到。
- **浮层不动**：队列浮层照今天画在 `Areas.content` 上（含义没变，所以频谱区开着时它照样看得见）；
  帮助与选择框照今天的做法以整帧居中（见 §8 的已知限制）。
- 播放栏、状态栏、桌面歌词覆盖层：**一律不动**。

## 5. 退化与错误处理

- **最小窗口（60×15）**：内容区 = 15 − 4 − 1 = 10 行；窗口高 15 < `MIN_LYRIC_HEIGHT`（20），
  所以歌词栏**不占位**——10 行全给列表（或频谱区），不会挤成一条缝。尺寸矩阵最紧的一档是窗口
  20 行（内容区 15 行）：歌词栏 `(15/3).clamp(5, 12)` = 5 行，剩下 10 行给列表或频谱区——
  每一段都 ≥ 5 行，画得下（尺寸矩阵归第一层 `TestBackend` 测试，见 §6）。
- 窗口高 < 20 行时按 `y` **不改变画面**（歌词栏在那个高度下本来就不占位），`v` 则拿到整个内容区
  ——这是高度规则的直接结果，不是键坏了。
- **提速档**：`spectrum_wanted()` 的判据从「全屏 + 在播」改成「**频谱区开着 + 在播**」；
  `spectrum_animating()`（33ms 那档）继续保持「`spectrum_wanted()` 且屏是 `Main`/`Home`」——
  登录屏不提速（它没有内容区）。
- 频谱区开着时按 `Esc`：**不再退频谱**（没有那层了），照常退层 / 清筛选 / 回首页。要退频谱按 `v`。
  这条状态行不再提示（提示只给 3–5 个最顺手的），`?` 里有那一行。

## 6. 测试计划

| 断言 | 位置 |
|---|---|
| `v` 在 `Content` 与 `Home` 都绑 `ToggleSpectrum`；`y` 在 `Home` 也绑 `ToggleLyric`；`Y` 在任何上下文都不再有绑定 | `keys.rs` |
| 模态浮层与输入态里 `v`/`y` 不抢（`None` / `InputChar`） | `keys.rs` |
| 四种合成：`v`/`y` 各自的开关只改自己（正交）；换屏（`1`..`4` / `0`）收掉频谱区 | `state.rs` |
| 歌词栏在有歌在放时**即使没有歌词**也占位（`phase = Playing`、`lyric = None`） | `state.rs`/`draw` |
| 频谱区开着时列表让位（`draw` 走频谱那条分支），`?` 帮助表里有 `v` / `y` 两行 | `draw/mod.rs` |
| 60×15 / 80×24 / 大窗口下：四种合成都不 panic、该在的都在界内 | `draw/mod.rs` |
| 真机（tuios，真二进制）：播放中 `y` 收起/展开歌词栏、`v` 进出频谱区、`v` + `y` 得到大频谱、换屏收掉频谱 | tuios |

**要重写或删除的现有测试**（都钉在「模式」上）：
`state.rs`：`only_a_playing_fullscreen_view_raises_the_frame_rate`、
`a_fullscreen_view_over_the_home_raises_the_frame_rate_too`、
`fullscreen_lyric_toggles_and_is_left_by_esc_or_switching`、`esc_leaves_the_fullscreen_before_popping_a_level`、
`the_home_fullscreen_view_uses_the_now_playing_context`、`home_key_in_the_fullscreen_view_collapses_it`；
`draw/mod.rs`：`fullscreen_lyric_takes_over_the_content_area`、
`the_now_playing_view_splits_into_spectrum_above_lyric`（标题与拆分比例都变了）；
`the_content_area_takes_the_full_width_at_any_window_size` **不用动**（`Areas` 与 `layout` 签名都没变）；
`keys.rs`：`Context::NowPlaying` 的键位表与「全屏里该没绑定」那两条（`press(Context::NowPlaying, …)` 的
各处）整段删；`uppercase_y_opens_the_fullscreen_view_and_hides_list_keys`、`the_home_screen_has_its_own_keys`
与 `Content` 的键位表里 `Y` 那两条要改。

## 8. 风险与已知限制

- **再没有「只看大频谱」的独立模式**是对的（那正是本次要拆的），但代价写清楚：频谱区最大就是
  内容区减歌词栏；要更大的频谱得等以后单独设计（本次非目标）。
- 频谱区开着时列表被替掉，`d`/`p`/`x`/`A`/`Enter` 这些键**仍然可用**（作用在看不见的列表上）。
  这是刻意的：没有模式，就不该有「按键随视图变脸」那套玄学。`Esc` 同理（不再退频谱）。
- 状态行在频谱区开着时给的是列表那套提示（不含 `v`）：想确认怎么退，按 `?`。
- **先前就有、本次不动**：帮助浮层与歌单选择框是以**整帧**居中的（`draw_help` / `draw_picker` 拿到
  的是 `frame.area()`），所以窗口矮的时候它们能盖住播放栏——跟代码里那句「浮层只盖内容区」的
  注释不符。队列浮层是画在 `Areas.content` 上的，没问题。本 spec 不碰这条，记在这里免得下次又
  当成新发现。

## 与旧决议的关系

`2026-10-11-tui-redesign-design.md` §10.4 的逐条处置：

| 旧决议 | 现在 |
|---|---|
| `Y` = 全屏歌词，只吃内容区，播放条与状态行不动 | 保留「只吃内容区」；`Y` 换成 `v`，吃的是「内容区 − 歌词栏」甚至整个内容区 |
| 全屏时底部不再单开一块（同一份歌词不画两遍） | **改成两栏并列**：频谱区在上、歌词栏在下——正是「不画两遍」的新形态（同一份歌词仍然只有一处） |
| 全屏时列表看不见，所以开 `Context::LyricFull`（现名 `NowPlaying`）只留看得见的键 | **推翻**：删掉这个上下文，列表键任何时候都可用 |
| `Esc` 层级里插一层（帮助 → 队列 → 选择框 → 输入框 → 全屏 → 筛选 → 退层） | **删掉全屏那一层**：帮助 → 队列 → 选择框 → 输入框 → 筛选 → 退层 |
| 数字键切屏顺手退出全屏 | 保留同样的行为，改名为「换屏收掉频谱区」（`switch_menu` / `go_home`） |
| 状态行在全屏时给「`Y`/`Esc` 退出 · …」 | **不再有专用提示**：`v` 进 `?` 帮助表 |
