# canto 首页（`0` 界面）设计

日期：2026-10-13
状态：待使用者复核

## 背景与目标

登录成功的落屏是写死的「我的收藏」：`finish_login()` 里 `self.screen = Screen::Main` +
`switch_menu(Menu::Favorites)`，启动时已经登录的那条路走 `load_initial()`，同样落到收藏。
于是「一进界面就是一屏歌」，能看见的入口只有内容区标题里那点暗示；切屏虽然数字键直达，
但**没有一处能把「有哪几屏、编号是几」摆给人看**。

本 spec 要一个**首页**：进主界面时落在它上面，它列出各屏的入口与编号，可以用 `j`/`k` 选、
`Enter` 进，也可以数字 `1..=4` 直跳。

范围只有导航层：不动各屏内部、不动网络层、不加配置项。**免登录**（启动不再要求会话）与
**本地音源**是另一轮的事，见「与旧决议的关系」——首页为此留位，但它自己不假设任何登录态。

## 非目标（YAGNI，明确不做）

- **不做免登录**：未登录仍然先进登录屏（那是 B1）。首页只负责「进了主界面之后先看什么」。
- **不做本地音乐 / 离线降级**（B2 / B3）。
- **首页不放副标题**（「我的收藏 489 首」这类条数）；也不放账号那一行——那要么多存一个昵称
  字段、要么显示 `uin`，都不值当。
- **首页不写操作提示**：上一轮刚把操作提示统一到状态行（`draw::hints`），首页再写一处就是
  第二个提示位。
- **不做「设置」屏**、不做可配置的首页条目顺序、不做首页条目的自定义增删。
- 不改各屏（收藏 / 歌单 / 搜索 / 历史）内部的键位与行为。

## 决策记录

| 决策 | 取值 | 理由 |
|---|---|---|
| 层的位置 | 新增 `Screen::Home` | `Menu` 的含义是「一份歌曲列表 + 选中位置 + 筛选」，首页不是列表。另一条路（`Screen::Main` 里加 `view: Home/Menu` 维度）省掉几处 match，但会让 `Menu`/`nav` 在首页下变成「暂时用不上的状态」，而首页偏偏还要靠它记住「上次停在哪一屏」 |
| 首页编号 | `0` | `1..=4` 已经是四屏；`0` 空着 |
| 首页内容 | 3 列网格（编号 + 名字，居中，4 项 = 3 + 1）+ 选中高亮 | 见「非目标」的两条 |
| 进屏 | `Enter` 或数字 `1..=4` | 数字直跳是现有行为，保留 |
| 回首页 | 任意屏按 `0`；列表顶部再按 `Esc` | 首页是最外一层；`Esc` 链末尾（`nav.pop_tracks()` 之后没得退时）多一步 |
| 回首页高亮 | 停在**刚离开的那一屏** | 跟「每屏各留一份选中位置」同一精神 |
| 首页的播放键 | 可用（`Space` `n/b` `←/→` `+/-` `m`） | 首页也能控制播放，跟全屏视图（`Y`）一个口径 |
| 首页不绑列表键 | `/`、`d`、`p`、`x`、`a`、`A`、`Shift+D` | 首页没有「选中的歌」；宁可不绑，也不给一个按了没反应的键 |
| 派发 | `Screen::Home` 也走 `App::apply()` | 与应用内按键、全屏视图同一条路径；差异靠键位表（`Context::Home`）与 `apply` 里两处屏判断，不另立一套 |
| 全局热键 | 首页也生效 | `dispatch_hotkey` 的门从 `Screen::Main` 扩成 `Main | Home`——两张屏都是「登录之后的主界面」 |

## 1. 状态与结构

```rust
pub(super) enum Screen {
    Login(LoginState),
    Home,
    Main,
}
```

- `App` 新增 `home_selected: usize`（0..4，落在 `Menu::ALL` 的下标上；不落盘，跟各屏选中位置
  一样退出即丢）。
- `keys` 新增 `Action::Home` 与 `keys::Context::Home`。
- **要动的地方逐条列出来**（`Screen` 是穷尽 match，漏一处编不过，但语义要一处一处定）：

  | 位置 | 改法 |
  |---|---|
  | `dispatch()` 的 `match self.screen` | `Screen::Home \| Screen::Main => self.apply(action)`（首页与主界面同一条派发路径） |
  | `apply_login()` 里粘贴 cookie 提交那个 `match`（现在只有 Login / Main 两支） | 加 `Screen::Home => return`（首页上不可能走到这条登录分支） |
  | `dispatch_hotkey()` 的门（现在 `if let Screen::Main`） | 扩成 `Main \| Home`——两张屏都是「登录之后的主界面」 |
  | `context()`（现在先判 Login，再判模态与全屏） | 模态（帮助 > 队列 > 选择框）与 `now_playing_full` 之后、`search_input` 之前加一支：`Home => keys::Context::Home` |
  | `draw()`（`draw/mod.rs`，现在是 Login 一支 + 主界面布局） | 主界面那支里再分首页 / 列表屏：首页画 `draw/home.rs` 那块 |
  | `finish_login()`（现在 `Screen::Main` + `switch_menu(Menu::Favorites)`） | 落屏改成 `Screen::Home`，且**不** `switch_menu`（不预取收藏） |
  | `load_initial()`（现在 `switch_menu(Menu::Favorites)`） | 改成落首页 |
  | `apply()` 的 `Back` 链末尾（现在最后一支是 `nav.pop_tracks()`） | 改成 `if !nav.pop_tracks() { self.screen = Screen::Home }`（`pop_tracks` 本来就返回 `bool`）。首页不在 `Context::Home` 里绑 `Esc`，所以这条链在首页上根本不会进——省掉一层「在首页要挡住弹层」的守卫 |
  | `apply()` 的 `Enter` / `move_selection()` / `select_edge()` / `Menu(n)` | 各加一处首页分支（见下） |

- `App::new()` 里的初值仍是 `Screen::Main`（它只活到 `tui::run` 决定落屏之前；`test_app()` 走
  这条路，现有测试因此不用改上下文）。

`apply` 里只有四处需要知道「现在在首页」（其余动作两张屏语义相同）：

1. `Enter`：首页 → 进选中那一屏（`switch_menu(Menu::ALL[home_selected])` + `Screen::Main`）
2. `Up`/`Down`/`First`/`Last`：首页 → 挪 `home_selected`（在 `move_selection`/`select_edge`
   开头加一支，跟帮助浮层优先于队列浮层同一处规矩）
3. `Menu(n)`：进屏时顺手 `Screen::Main`
4. 回首页那一步（`0`、以及 `Back` 链末尾）把 `home_selected` 设成 `Menu::ALL` 里 `nav.menu`
   的下标——「停在刚离开的那一屏」就是它

## 2. 键位（`Context::Home`）

| 键 | 动作 |
|---|---|
| `j` / `k` / `↑` / `↓` | 上下挪选中 |
| `g` / `G` / `Home` / `End` | 首 / 尾 |
| `Enter` | 进选中那一屏 |
| `0` | 回首页（已经在首页 = 无操作） |
| `1`..`4` | 直达那一屏 |
| `Space` `n` `b` `←` `→` `+` `-` `m` | 播放控制，跟主界面一致 |
| `u` / `Y` | 队列浮层 / 全屏正在播放 |
| `?` / `F1` | 帮助 |
| `L` | 登出 |
| `q` / `Ctrl-C` | 退出 |
| **不绑** | `Esc`（首页在最外层，没有可退的——不绑比绑成空操作更省事）、`/`、`d`、`p`、`x`、`a`、`A`、`Shift+D`、`PgUp`/`PgDn` |

`Action::Home` 在 `Context::Content` 与 `Context::NowPlaying` 也绑（`0` 从任何主界面位置回首页），
模态浮层与输入态**不绑**——`0` 在那儿的含义是打字 / 浮层的键。

状态行提示（`hints`）：`Enter 进入 · 1-4 直跳 · Space 暂停 · n/b 切歌 · u 队列 · ? 帮助`。

## 3. 导航规则

| 从 | 动作 | 到 |
|---|---|---|
| 登录成功 / 启动时已登录 | — | 首页（**不再预取收藏**：`favorites_loaded` 保持 false，谁进收藏屏谁拉） |
| 首页 | `Enter` / `1`..`4` | 那一屏（`switch_menu` + `Screen::Main`），全屏视图跟着收起（现有行为） |
| 任意主界面屏 | `0` | 首页（全屏视图里也能按，先收起全屏） |
| 列表顶部（没进歌单、没开筛选、没开浮层） | `Esc` | 首页 |
| 首页 | `Esc` | 无绑定（`Context::Home` 里没有它；首页没有上一层可退） |

回首页时 `home_selected` 落在刚离开的那一屏；从登录屏进来（`finish_login`）落在第一项。

## 4. 绘制

```text
┌ 首页 ──────────────────────────────────────┐
│                                            │
│      ┌───────────┐ ┌───────────┐ ┌───────┐ │
│      │▶ 1  我的收藏│ │  2  我的歌单│ │ 3  搜索│ │
│      └───────────┘ └───────────┘ └───────┘ │
│      ┌───────┐                             │
│      │  4  历史│                             │
│      └───────┘                             │
│                                            │
└────────────────────────────────────────────┘
```

- `src/tui/draw/home.rs`：内容区那一块，格由 `Menu::ALL` 生成（编号 = 下标 + 1），按 **3 列
  换行**（4 项 = 3 + 1，`ceil(n/3)` 行）、整块在内容区里**水平 + 垂直居中**；每格一个等宽
  带框小方块，选中的那格加 `▶ ` 与既有 `highlight()`。
- 面包屑（`Nav::title_chain()`）不动：首页不走它，标题直接是「首页」。
- 状态行、播放条、底部歌词块、队列浮层、全屏视图照旧——首页只是内容区换了一块。
- 帮助表（上一轮的 `help_rows`）：「切屏」段加一行 `0  首页`；首页上的提示由状态行给。
- 尺寸：四格在最小窗口（60×15，内容区 10 行）里画得下（3 列 ≈ 55 列 × 7 行）；过小窗口仍走
  既有 `too_small` 文案。

## 5. 退化与错误处理

- 首页**不花任何网络请求**、不读会话：`Menu::ALL` 与标题都是静态数据，所以它天然不受
  未登录 / 断网影响（B1 落地时直接可用）。
- 首页上的列表键不绑，因此不存在「按了没反应」或「弹一句没有选中」的通知。
- `finish_login` 不再顺手拉收藏：登录后落到首页时状态行不再有「加载中」进度（这是有意的
  ——谁进收藏屏谁拉，跟其它屏一致）。

## 8. 风险与已知限制

- **落屏变了**：老用户一进来是首页、不再是收藏（多按一次 `Enter` 或直接 `1`）。这是本 spec
  的目的，但 README 里要说一句。
- **`Esc` 在列表顶部不再是「无操作」**：现在会回首页。这是有意改的（首页是最外一层），代价
  是按错一下会离开当前屏——但选中位置留着，`Enter`/数字回去还在原处。
- **首页条目暂时就是 `Menu::ALL`**：B2 的「本地音乐」不是 QQ 的菜单，届时首页需要自己的
  条目表（`Entry` 枚举或 `Menu | Local`），那一步在 B 的 spec 里做，本 spec 不预留占位行。
- **首页不显示条数**：想「一眼看出收藏有多少首」得进那一屏。数字要拉数据才能有，不值得。
- 首页的 `Y` 全屏视图在内容区是歌词 + 频谱（列表看不见），与列表屏一致；首页本身没有「正在
  播放的那首」的概念，所以不额外做高亮。

## 与旧决议的关系

- `2026-10-11-tui-redesign-design.md`：「数字键是唯一入口」——现在多了一个**看得见的**首页
  （编号 `0`），数字键仍是唯一的直接入口，只是多了一处把它们列出来的地方。
- `2026-10-12-global-hotkeys-design.md`：「热键只在 `Screen::Main`」——首页算主界面，门扩成
  `Main | Home`；动作与派发路径不变。
- **B（免登录 + 本地音源）另起一轮**，分 B1（启动不要求会话）、B2（本地音源：目录扫描 /
  元数据 / 本地 `Track` 形态）、B3（未登录时在线屏的降级表现）。本 spec 的首页不读会话、不发
  请求，B1 落地后它直接就是「没登录也能进的第一屏」；B2 的「本地音乐」会成为首页条目表里的
  第 5 行。
