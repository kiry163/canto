# 本地曲库与本地歌单（设计）

**日期：** 2026-10-13
**状态：** 待评审
**取代：** 无（本次是新增子系统；与 `2026-10-13-content-area-panels-design.md` 无冲突）

## 背景与目标

使用者在 2026-10-13 提的原话：

> 我认为现在因为是**必须强制 QQ 登录**，这个体验可能不好，**并且无法直接在无网络的情况下进行
> 本地歌曲播放**……

两个痛点其实是同一件事的两面：**canto 今天离开「QQ 登录 + 网络」就一步都走不了**。查实的现状：

- 启动只决定一次落屏（`tui/mod.rs:63-67`）：有登录态 → 首页，否则 → **登录屏**，且一进登录屏就
  spawn 取二维码（`state.rs:1485-1488`）——没网时这一步必然失败，使用者连界面都进不去。
- 播放链路的每一环都挂 QQ：`Song.mid` 是**全链路唯一键**（`♪` 标记、缓存命中、历史重播都按它
  比对），播一首必须先拿 vkey 换 CDN 地址（`state.rs:1001-1032` → `engine.play(Track)`，
  `Track = Song + 一组候选 URL`，`player.rs:33-36`）；缓存只是「顺序听完」的副产物
  （`cache.rs:194-282`），落 `~/.cache/canto/<mid>.<档位>.<ext>`，且**命中也省不掉 vkey 那一跳**。
- 没有任何本地文件入口：CLI 只有 `--log`、不读音频 tag、不读同目录 `.lrc`；`media.rs` 的
  `MediaSource` 只有「网络流 / 缓存文件」两种。

**目标**：登录与网络都变成**可选**。没登录、没网时 canto 依然完整可用——扫本地目录、放本地歌、
按本地歌单组织、看歌词与频谱；登录且有网时，QQ 那一套（收藏 / 歌单 / 搜索 / 历史 / 下载）照旧，
两边的歌进同一个队列、同一份历史。

**成功标准**（真机可验）：清掉会话文件后启动，落在首页、`--log debug` 里**零 HTTP 请求**；进
「本地曲库」能播 `Music\canto` 里的歌（歌词栏、频谱、桌面歌词照常工作）；`P` 能把歌加进本地歌单，
`6` 能进去看到它；`L` 能去登录屏，`Esc` 能回来。

## 非目标（YAGNI，明确不做）

- **不做会话续期**（使用者明确否掉）：jar 里的 `psrf_qqrefresh_token` 之类继续躺着不读；过期了就
  回登录屏由使用者自己重登。
- 不做多账号 / 多会话（现状单 `session.json` 不变）。
- 不做本地歌单的手动排序、嵌套、导入导出、删除确认以外的批量操作。
- 不做封面（`Playlist.cover_url` 今天就没渲染，本地也不引入）。
- 不做字幕级功能：CUE 分轨、内嵌封面、Opus/ALAC/APE/WMA 等扩展格式（见 §8 格式边界）。
- 不做目录监听（`inotify`/`ReadDirectoryChangesW`）：靠索引 + `r` 手动重扫。

## 决策记录

| 决定 | 取值 | 为什么 |
|---|---|---|
| 拆分 | **只做「本地曲库 + 免登录可达」**，不做登录续期 | 使用者原话；「登录变成可选」本身就去掉大半登录痛，续期是纯逆向未知且不解决离线 |
| spec 与计划 | **一个 spec，实施计划分两阶段**（阶段一：曲库 + 免登录；阶段二：本地歌单） | 两件事共享数据模型，但阶段一独立可用 |
| 曲库范围 | **可配置目录表**（默认含 `download_dir`），递归扫描，**读内嵌 tag**，文件名兜底 | 使用者选的 B；canto 自己下载的文件带 ID3（实测 `title/artist/album` 都在），但真曲库不能指望文件名 |
| 元数据库 | **`lofty`**（新依赖，纯 Rust） | 一次拿到 tag + 时长 + 内嵌歌词；备选是复用树里的 symphonia metadata（零新依赖但覆盖窄、歌词要自己拼），不值 |
| 元数据落盘 | **`~/.cache/canto/library.json` + 后台按 `mtime`/size 增量补扫**，`r` 全量重扫 | 读 tag 是磁盘密集型；不落盘就得每次启动白扫一遍，启动期现扫又会卡住界面 |
| 本地屏形态 | **扁平文件列表**（`/` 筛选照旧），排序 = 歌手 → 专辑 → 标题 | 使用者选的 A；专辑天然相邻，不需要两级界面 |
| 数据模型 | **路线甲**：`Song` 增 `source` 字段，本地曲目 `mid = "local:<绝对路径>"` | 队列 / 历史 / `♪` / 歌词 / 渲染全都不用改签名；代价是对本地无意义的字段用 0/None 占位 |
| 未登录首页 | **永远六格**，未登录进 QQ 三屏只提示不跳屏 | 使用者定的：格子常驻（发现性），`需要登录：按 L` 一句话说清 |
| 未登录的「历史」 | **可进，但只列本地条目** | 使用者定：「未登录播放的历史歌曲是 QQ 歌曲直接跳过」 |
| 未登录的登录入口 | `L`（未登录 = 去登录屏；已登录 = 登出） | 同一个键的两个方向，语义对称；登出**不再清队列**（本地歌接着放） |
| 启动取码 | **只在真的进登录屏时取**，启动不再取 | 没网时启动必须零请求 |
| 本地歌单的持久化 | `~/.config/canto/local-playlists.json`，条目存**合成 mid + 标题/歌手快照** | 文件被移走/改名后条目还在（标「已丢失」）；不因一次扫描清空使用者的歌单 |
| 加入本地歌单的键 | **`P`（大写）**，QQ 侧仍是 `p`（小写） | 使用者定的：两套歌单分开，键也分开 |
| 重名歌单 | **拒绝**（去首尾空白后非空、且不与已有重名） | 选择框里两个同名歌单认不出来 |
| 删整张歌单 | **`D` 双按确认**（第一次只出一句「再按一次 `D` 确认删除」） | 歌单是使用者自己建的，跟 `Shift+D` 清队列那种无确认破坏键不是一个量级 |

## 1. 概念与术语

| 名字 | 是什么 |
|---|---|
| **本地曲库** | 扫描出来的本地音频文件集合（索引 + 内存里的 `Song` 列表）。首页第 5 格 |
| **本地歌单** | 使用者从本地曲库挑出来组织的列表，落 `local-playlists.json`。首页第 6 格 |
| **合成 mid** | 本地曲目的键：`local:<绝对路径>`。前缀保证永不与 QQ 的 mid 相撞，且一眼可辨 |
| **曲库索引** | `~/.cache/canto/library.json`：扫描结果的缓存（派生数据，删了只会重扫一次） |
| **已丢失** | 本地歌单里的条目所指文件现在不在（同一次扫描没扫到）时的显示与播放行为 |

## 2. 数据与索引

### 2.1 数据模型改动

```rust
// src/model.rs
#[derive(Default)]           // Source 自己默认 Qq
enum Source { #[default] Qq, Local(PathBuf) }

struct Song {
    #[serde(default)]        // QQ 接口的 JSON 里没有这个字段，靠 default 走 Qq
    source: Source,          // 新增
    ..                       // 其余不动
}
```

- 本地曲目字段映射：`mid = local:<路径>`、`title`/`singers`（= tag 的 artist）/`album_name`/
  `duration_secs` 来自 tag；`sizes`/`media_mid`/`album_mid`/`song_id` 留空 → 列表体积列走现有的
  `—` 降级，`album_mid` 不影响任何现有逻辑。
- 配套两个纯函数（单测钉住）：`local_mid(path) -> String` 与 `local_path(mid) -> Option<PathBuf>`。
- 排序：`(singers, album_name, title)`，缺 tag 时用文件名（没有扩展名）兜底；同一目录的文件因此
  天然相邻。

### 2.2 索引文件

```json
{ "version": 1,
  "dirs": ["C:\\Users\\28269\\Music\\canto"],
  "entries": [ { "path": "…", "mtime": 1712345678, "size": 4321054,
                 "title": "曲终人散", "artist": "张宇", "album": "消息",
                 "duration_secs": 270 } ] }
```

- `version` 或 `dirs` 与当前配置不符 → 整份丢弃重扫（一句 `warn`，不弹窗、不阻断启动）。
- 读索引失败（损坏/半截）→ 同上按空处理。

### 2.3 扫描（后台线程 + 消息）

- 触发：启动（读完索引立刻可用之后）、`r`（全量，丢弃索引）、配置目录列表变化后首次启动。
- 过程：递归遍历配置目录 → 跳过点开头目录、不跟软链、扩展名白名单（§8）→ 只对**新增或
  `mtime`/`size` 变了**的文件读 tag → 消失的条目删掉 → 写回索引（`tmp` + `rename`，沿用
  `history.rs:57-70` 那套原子写法）。
- 进度：扫描期间「本地曲库」屏的标题带「扫描中 N 首」；扫描完成时**只在真有变化**时给一句状态行
  通知（`本地曲库：新增 M · 移除 K`），无变化不打扰。
- 并发：同时只允许一次扫描；扫描中按 `r` → 忽略 + 一句「正在扫描」。

### 2.4 歌词（本地曲目，全程零网络）

按顺序找，命中即用：① 音频**同目录同名** `.lrc` → ② `config.lyrics_dir` 里的同名 `.lrc`
（canto 自己下载的歌词就在那儿，`download.rs:160-186`）→ ③ **内嵌歌词**（`lofty`）。
命中后仍写进现有歌词缓存（key = 合成 mid），桌面歌词那一套照旧工作；都没有就显示「暂无歌词」。

### 2.5 历史

`history.rs` 的 `Entry` 增一个可选字段（`#[serde(default)]`，老 `history.json` 照读）：

```rust
struct Entry { mid, title, singers, at, origin,
               local_path: Option<PathBuf>,   // 新增
}
```

- 本地条目写入时带上 `local_path`，重播不再经过 vkey。
- **未登录时「历史」屏只列本地条目**（QQ 条目在视图层过滤掉，见 §3.3）。

## 3. 免登录可达性

### 3.1 首页六格

`Menu::ALL` 增加两项，编号就是下标 + 1（`home.rs` 现有规则）：

| 编号 | 屏 | 未登录 |
|---|---|---|
| `1` | 我的收藏 | 进不去（提示） |
| `2` | 我的歌单 | 进不去（提示） |
| `3` | 搜索 | 进不去（提示） |
| `4` | 历史 | **可进**（只列本地条目） |
| `5` | 本地曲库 | 可进 |
| `6` | 本地歌单 | 可进 |

### 3.2 落屏与登录入口

- `load_initial`（`tui/mod.rs:63-67`）：有登录态 / 没有登录态**都落首页**——首页自己按登录态决定
  哪些格能用（格子在两种状态下都画，不再隐藏）。
- 未登录进 `1`/`2`/`3`（数字直跳、`Enter`、`Esc` 返回都算）：状态行一句
  **`需要登录：按 L`**，不跳屏、不发请求。
- `L`：未登录 → `Screen::Login`（**这时候才**取二维码）；已登录 → 登出（清会话）→ 回首页，
  **队列保留**（本地歌继续放，轮到 QQ 歌才提示需要登录）。
- 登录屏新增 `Esc` = 回首页（今天只能 `q` 退出或重来）；登录成功照旧 `go_home()`，且**不打断正在
  播放的本地歌**（不清队列、不重建引擎）。
- 顺带修文案：`qq/mod.rs:35` 那句还在引用**已不存在的命令**（`canto login --cookie '<cookie>'`）
  的提示，统一改成 `需要登录：按 L`。

### 3.3 未登录时的能力边界

| 能力 | 未登录 |
|---|---|
| 本地曲库 / 本地歌单 / 本地歌播放 | 全功能 |
| 历史（只列本地条目）+ 重播本地条目 | 可用 |
| 歌词（本地查找）/ 歌词栏 / 桌面歌词 / 频谱 / 播放条 / 队列 | 可用 |
| 全局热键（播放/切歌/音量/歌词锁） | 可用（不需要登录） |
| 收藏 / 我的歌单 / 搜索 / 下载 / 加 QQ 歌单 | 一句 `需要登录：按 L` |

## 4. 本地曲库屏

- 与现有列表屏同一套交互：`j`/`k`、`g`/`G`、`PgUp`/`PgDn`、`/` 筛选、`Enter` 播、`a`/`A` 入队。
- `P`（大写）= **加入本地歌单**：弹出现在那个歌单选择框（`keys::Context::*Picker` 那一套）的本地
  版——列出本地歌单（带曲目数）+ 第一行「新建…」（选中即输入名字并建、顺手把这首加进去）。
- `p`（小写）= 加入 QQ 歌单：需登录；未登录时给 `需要登录：按 L`。
- `r` = 全量重扫。
- **不绑**：`d`（下载）、`x`（从歌单移除）——本地没有 QQ 上下文，宁可没反应也不给假许诺。状态行与
  `?` 帮助表也不列这两个键（帮助表的「歌曲」那一段按屏分岔）。
- 列表列渲染沿用现有 `content.rs`：标题 + 歌手 + 时长（未知 `--:--`）+ 体积列 `—`；`♪` 标记照旧
  （按 `mid` 比对，本地就是路径）。
- 曲库为空时显示一句「曲库是空的：在 `config.toml` 的 `[library] dirs` 里加目录」，不是空白列表。

## 5. 本地歌单

### 5.1 存储

`~/.config/canto/local-playlists.json`（`paths.rs` 新增一个函数）：

```json
{ "version": 1,
  "playlists": [ { "name": "通勤",
                   "songs": [ { "mid": "local:C:\\…\\张宇 - 曲终人散.mp3",
                                "title": "曲终人散", "singers": "张宇" } ] } ] }
```

- 写盘用 `tmp` + `rename`（同 history）。任何一次 CRUD 立刻落盘。
- 条目只存 mid + 快照：路径对得上就在每次渲染时从曲库索引取实时时长，对不上就显示
  `（已丢失）`，播的时候状态行给一句「文件不在了：<路径>」。
- 歌单里的歌按**加入顺序**排，不支持手动排序。

### 5.2 屏与键

与「我的歌单」同构（左列表 → `Enter` 进去列曲目；`Esc` 回歌单列表；空歌单可进并显示「空歌单」）：

| 键 | 作用 |
|---|---|
| `n` | 新建歌单（输入名字：去首尾空白、非空、不与已有重名，否则提示） |
| `R` | 重命名当前歌单（同上校验） |
| `x` | 从当前歌单移除选中曲目 |
| `D` | 删除整张歌单：第一次只出一句「再按一次 `D` 确认删除」，第二次才真删（任何别的键都取消这次待确认） |
| `Enter` / `Esc` | 进歌单 / 回上一级 |

- 输入名字沿用现有输入行那套（跟 `/` 筛选、登录屏粘 cookie 同一个模型），`Esc` 取消。
- 屏内的状态行提示与 `?` 帮助表跟着这屏的键走（列 `n`/`R`/`x`/`D`，不列 `d`/`p`/`P`）。

## 6. 播放链路

- `Track` 的字节来源分成两支（`player.rs:33-36`）：

```rust
enum TrackSource { Cdn(Vec<Candidate>), Local(PathBuf) }
```

- `state.rs` 的播放入口按 `song.source` 分岔：`Local` → **直接**构造 `Track { source: Local(path) }`，
  **不调 vkey、不发任何请求**；`Qq` → 现有链路。
- `player.rs::open()` 增一条分支：`Local` 直接 `File::open` + `Decoder::new(MediaSource::File)`；
  **不写播放缓存**（没必要，文件本身就在盘上）；失败 → `Phase::Failed`，状态行
  `打不开：<原因>`（文件没了 / 权限 / 解码器认不出）。
- 其余全部不动：`LevelMeter` 包装、频谱、播放条时长（解码器实测）、歌词栏、桌面歌词。
- 本地歌与 QQ 歌可同队列、同历史；混排下 `n`/`b` 只按队列走，轮到 QQ 歌而未登录时给
  `需要登录：按 L`（并把这首标成失败，不静默跳过）。

## 7. 配置

```toml
# config.toml
[library]
# 本地曲库目录（递归），默认 = download_dir 那一项
dirs = ['C:\Users\28269\Music\canto']
```

- 缺省（没有 `[library]` 段）→ `dirs = [download_dir]`。
- `dirs = []` → 本地功能整体关闭：首页第 5/6 格不画（其余照旧）。
- 目录不存在 / 没权限 → 跳过该目录 + 一句点名通知，**不阻断启动**。
- 相对路径按当前工作目录解析（与 `download_dir` 现有语义一致）。

## 8. 边界与错误

| 情况 | 行为 |
|---|---|
| 扩展名不在白名单 | 不扫、计数，扫完一句「跳过 N 首不支持的格式」 |
| 白名单 | `mp3` `flac` `m4a` `mp4` `ogg` `wav`（= 现有解码器能解的那套：mp3 / flac / m4a-AAC / ogg-Vorbis / wav） |
| 文件能扫但解不出（如 m4a 里的 ALAC） | 列进曲库；播的时候报 `打不开：…`（不预先试探解码，太贵） |
| 读 tag 失败 | 用文件名当标题、歌手未知、时长未知（列表 `--:--`） |
| 时长未知 | 列表显示 `--:--`（不再用会骗人的 `00:00`；历史屏本来就不画时长） |
| 同一路径被多个配置目录覆盖 | 去重 |
| 文件名不是合法 UTF-8（Windows 罕见） | 路径按 lossy 转换，能扫能播，只是显示可能带替换符 |
| 索引损坏 / 版本不符 | 丢弃重扫，`warn` 一句 |
| 扫描中按 `r` | 忽略 + 一句「正在扫描」 |
| 曲库为空 | 列表区显示配置引导句（见 §4） |
| 播放本地文件失败 | `打不开：<原因>`，停在这一首 |

## 9. 测试计划

**单测（`cargo test`，与代码同文件；临时目录树 + 哑引擎，不需要网络与声卡）**

- 扫描器：收/跳规则（点开头目录、软链、扩展名白名单、去重）、tag 缺失回落文件名、时长解析、
  不支持格式计数。
- 索引：写入/读回、`version`/`dirs` 不符重扫、只重读 `mtime`/`size` 变了的项、消失项被删、
  损坏文件按空处理。
- 合成 mid：`local_mid`/`local_path` 往返（含 Windows 盘符与空格路径）。
- 历史：带 `local_path` 的条目重播走本地分支；**旧 `history.json`（没有该字段）照读**。

## 11. 风险与已知限制（写进 `docs/design.md`）

- **路径就是身份**：本地曲目移动/改名 = 变成另一首（历史与歌单条目显示「已丢失」）。这是「不做
  内容哈希」换来的简单（哈希要读整文件，大曲库首扫会慢到不可接受）。
- **索引是 `~/.cache` 下的派生物**：删了只会重扫一次；`~/.config` 里只放使用者自己建的歌单。
- **首扫时间与曲库大小成正比**（读 tag 是 IO）；第二次起靠索引 + `mtime` 增量。
- **Windows 路径大小写**：去重按原样字符串比对，同一个文件用不同大小写写进配置会当成两首。
- **未登录时 QQ 屏仍然画出来**（只是进不去）：这是刻意的发现性取舍，不是遗漏。
- 缓存那条老限制（README「缓存只收顺序听完的歌，所以不等于离线模式」）**要改写**：本地曲库才是
  离线方案，播放缓存仍然只是播放缓存。
