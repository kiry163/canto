# canto

自用的 QQ 音乐播放器（Rust）。**所有功能都在终端界面里**——登录、歌单、播放、歌词、搜索、下载、播放历史。

界面由一块内容区（标题就是你所在的位置）+ 常驻的播放条与状态行组成；内容区里还能再开**歌词栏**（`y`）与**频谱区**（`v`）两个栏。键盘优先，不碰鼠标。

## 功能

| 能力 | 状态 |
|---|---|
| 登录：界面内扫码（二维码画在终端里）/ 粘贴 cookie | ✅ |
| 在线收藏 / 在线歌单（含音质档位） | ✅ |
| 首页（`0`）：进界面先落在屏入口列表上，`j`/`k` 选、`Enter` 进、数字直跳 | ✅ |
| 播放：vkey 取流 → 边下边解码出声 | ✅ |
| 显式队列：追加 / 插队 / 删除 / 清空 / 跳播 + 四种播放模式 | ✅ |
| 播放历史（落盘、可重播、可清空） | ✅ |
| 歌词（行级 + 翻译，当前句**居中**高亮；`y` 开 / 关底部**歌词栏**，没有歌词也画；歌词本身也缓存） | ✅ |
| 可视化：`v` 开 / 关**频谱区**（对音频采样做 FFT + 对数分频）——它与列表互斥，歌词栏不在时吃满整个内容区 | ✅ |
| **本地曲库**（`5`，`[library] dirs` 递归扫、读内嵌 tag、索引落盘）：不登录、没网也能听；本地歌进同一个队列 / 历史 | ✅ |
| **本地歌单**（`6`，自己建的，落 `~/.config/canto/local_playlists.json`）：曲库里按 `P` 把歌加进来；文件被移走 / 改名也不丢条目（标「（已丢失）」） | ✅ |
| 在线搜索（独立一屏，不顶掉正在看的歌单） | ✅ |
| 列表内筛选（`/` 输入即筛，独立于搜索） | ✅ |
| 下载（歌曲进下载目录，`.lrc` 进独立歌词目录；已缓存的歌直接复制） | ✅ |
| 播放取源：起播先看本地——**缓存 > 下载目录 > 线上取流**，`●` 已缓存 / `↓` 已下载那两行重听 0 网络；播放条那一格写着来源（`[缓存 MP3 320k 10.3MB]` / `[下载 3.6MB]` / `[在线 MP3 128k 2.3MB]` / `[曲库 FLAC 27.2MB]`） | ✅ |
| 播放缓存（完整听过的歌留在 `~/.cache/canto`，重听直接读它） | ✅ |
| 歌单写入：加进歌单 / 从歌单移除（「我喜欢」只读，见「已知限制」） | ✅ |
| 配置文件 `config.toml`（音质下限 / 目录 / 缓存与历史上限 / 通知存活秒数 / 全局快捷键 / 桌面歌词） | ✅ |
| 全局快捷键：canto 在后台时也能播放 / 暂停、上下一首、音量 ±5、开 / 关桌面歌词、切歌词锁定（Windows / macOS，可配可禁） | ✅ |
| 桌面歌词（Windows / macOS，默认开）：当前句 + 翻译 + 下一句浮在桌面之上，默认鼠标穿透、热键解锁后可拖 | ✅ |
| 单例运行（同一份数据目录只允许一个实例） | ✅ |

## 平台

macOS / Linux / Windows 三平台都能跑（**全局快捷键与桌面歌词只在 Windows / macOS 生效**，见「已知限制」）。
Release 页面上的产物都由 CI 编（`release.yml`），本地不用
再交叉编译：

| 产物 | 对应平台 | 运行时的额外依赖 |
|---|---|---|
| `canto-aarch64-apple-darwin.tar.gz` | macOS Apple Silicon | 无（只用系统库） |
| `canto-x86_64-unknown-linux-gnu.tar.gz` | Linux x86_64 | 系统要有 `libasound2`（ALSA；在 Ubuntu 22.04 上编的，glibc ≥ 2.35） |
| `canto-x86_64-pc-windows-msvc.zip` | Windows x86_64 | 无（静态 CRT，不用装 VC++ 运行库） |

Intel 芯片的 Mac 不在 Release 里（GitHub 也在逐步下线 `macos-*-intel` 镜像）：那种机型自己
`cargo build --release` 编一份即可，代码本身是支持的。

包里就是一个可执行文件，解压完在终端里敲 `./canto`（Windows 是 `canto.exe`）。它需要一个能画框的
终端；启动时会打开默认音频设备，**没有声卡会直接报错退出**（不是等到第一次播放才报）。

## 用法

```bash
cargo run                 # 进界面（默认命令，也是唯一的命令）
cargo run -- --log info   # 把播放细节写进日志文件
cargo run -- --help       # 只有 --log / --version
```

首次运行自动生成 `config.toml`；没有有效会话时界面先出**登录屏**：二维码画在终端里扫码登录。
二维码按**模块**画（一个字符格宽 = 一个模块），33×33 的码只占 **37 列 × 19 行**——普通终端都
装得下，终端越大自动画得越大（1 / 2 / 4 倍）。真装不下（不到 **38×23**）会告诉你需要多大，
并给 `c`（粘贴 cookie）与 `o`（用系统查看器打开二维码图片）两条路。同一份数据目录**只允许一个
canto 在跑**：第二个实例直接退出并报出持有者的 pid（锁在 `~/.config/canto/canto.lock`，跟着进程走，
退出即释放；Windows 上锁是强制的，第二个实例读不到锁文件内容，所以只报「已经有一个在跑」）。
日志写文件 `~/.config/canto/canto.log`——屏幕归界面，往 stdout/stderr 打印会糊屏。

界面大概长这样：

```
┌ 在线歌单 › 嗯 42 首 ──────────────────────────────────────────────────────┐
│ ▶ 04:36 FLAC 27.2MB 山水之间 — 许嵩                                       │
│   02:52 FLAC 24.8MB 非酋 — 薛明媛、朱贺                                   │
│                                                                           │
└────────────────────────────────────────────────────────────────────────────┘
┌ 歌词 ─────────────────────────────────────────────────────────────────────┐
│                      昨夜同门云集                                         │
│ ▶                    推杯又换盏                                           │
└────────────────────────────────────────────────────────────────────────────┘
┌ 播放 ─────────────────────────────────────────────────────────────────────┐
│ ♪ 非酋 — 薛明媛、朱贺 [在线 FLAC 24.8MB] 播放中 · 顺序 · 3/42 · 音量 100% │
│ ██████████████░░░░░░░░░░░░░  01:32 / 02:52                                │
└────────────────────────────────────────────────────────────────────────────┘
 Enter 播放 · Space 暂停 · n/b 切歌 · / 筛选 · p 加歌单 · ? 帮助   已插队《晴天》
```

状态行左边永远是当前可用键的提示，右边是**一条通知**（固定 32 列）：加载进度、动作结果、错误
都写在那儿，`notice_seconds` 秒后自己消失。列表条数不占这块——它挂在内容块标题上
（`在线歌单 › 嗯 42 首`）。

## 键位

没有菜单栏，内容区吃满全宽，切屏用数字键 `1`–`4`；小于 60×15 只显示一行「终端太小」。
完整键位表在 `?` 帮助浮层里（那是唯一一份）。

| 键 | 作用 |
|---|---|
| `0` | 回首页：六屏入口的 3 列网格（居中，编号 + 名字），`Tab`/`Shift+Tab` 挪格（到头会绕回去）、`Enter` 进、`1`–`6` 直跳；它就是登录后的落屏 |
| `1`–`6` | 切屏：`1` 在线收藏 · `2` 在线歌单 · `3` 在线搜索 · `4` 播放历史 · `5` 本地曲库 · `6` 本地歌单（**唯一的直接入口**；从首页按也一样） |
| `j` `k` / `↑` `↓` | 移动选择（**列表、队列浮层、歌单选择框、帮助浮层**；首页那排菜单格用 `Tab`/`Shift+Tab`，这两类键在首页上没绑定） |
| `g` `G` / `Home` `End` | 首 / 尾 |
| `PgUp` `PgDn`（`Ctrl+U` `Ctrl+D`） | 翻页 |
| `Enter` | 歌单列表 = 进入该歌单的曲目；曲目列表 = 以此列表开新队列并从该首播 |
| `Esc` / `Backspace` | 返回上级 / 取消输入 / 关浮层 |
| `Space` | 播放 / 暂停 |
| `n` / `b` | 下一首 / 上一首（按当前模式走） |
| `←` `→`（`h` `l`） | 后退 / 前进 10 秒 |
| `+` `-`（`,` `.`） | 音量 ±5% |
| `m` | 播放模式：顺序 → 列表循环 → 单曲 → 随机 |
| `a` / `A` | 追加到队尾 / 插到下一首 |
| `u` | 队列浮层（只盖内容区，播放条与状态行照旧；`j` `k` 选 · `Enter` 跳播 · `d` 删除 · `Shift+D` 清空） |
| `p` | 把选中曲目加进某个歌单 |
| `x` | 从当前歌单移除选中曲目（「我喜欢」见「已知限制」） |
| `d` | 下载选中曲目（含同名歌词） |
| `y` | 歌词栏开 / 关（内容区底部那一条；没有歌词也画，写「暂无歌词」） |
| `v` | 频谱区开 / 关（与列表互斥；歌词栏不在时吃满整个内容区） |
| `5` | **本地曲库**（`[library] dirs` 扫出来的曲目；`r` 重扫。本地歌不参与下载；加歌单走 `P`） |
| `6` | **本地歌单**（自己建的；`N` 新建 · `R` 改名 · `x` 移出选中那首 · `D` 连按两次删整张；名字输入 `Enter` 确认、`Esc` 放弃） |
| `P` | 把选中的本地曲目加进本地歌单（**只在「本地曲库」屏**；选择框第一行固定是「新建…」，选它就直接问名字、建好顺手把这首加进去） |
| `/` | **筛选当前列表**：输入即筛，`Enter` 确认（筛选留着，接着 `Enter` 就播这一队），`Esc` 清空；筛选生效后再按 `Esc` 也能清 |
| `j` `k`（`↑` `↓`） | 上下移动选中：列表、队列浮层、歌单选择框、帮助浮层（在帮助里是滚动）都给同一套；`g`/`G`、`Home`/`End` 跳首尾 |
| `Tab` `Shift+Tab` | **只挪首页那排菜单格**（到底 / 到顶会绕回另一头）；列表那几处照旧用 `j`/`k` 与 `↑`/`↓`，首页上这两类键没绑定 |
| `L` | 登出（清空本地会话，回登录屏）；`l`（小写）是快进 10 秒，别弄混 |
| `?`（或 `F1`） | 帮助浮层：左侧按键、右侧说明的表格，按当前屏列出可用键，末尾一栏是 `[hotkeys]` 里那几条全局热键（现读配置、禁用的不列）；`j`/`k`、`↑`/`↓`、`g`/`G` 滚动，怎么关 / 怎么滚看状态行 |
| `q` / `Ctrl-C` | 退出 |

两条用得上的语义（其余细节见 `docs/design.md`）：

- **切屏**：数字键是唯一的直接入口（`1`–`6`），按下去就是回到那一屏上次的位置（面包屑跟着还原）；退层用 `Esc` /
  `Backspace`。**登录后落在首页**（`0`）——它把六屏的入口与编号排成 3 列网格（居中），`j`/`k` 选、`Enter` 进；
  在列表顶部（没进歌单、没开筛选）再按 `Esc` 也回首页，首页自己按 `Esc` 没有绑定。
  输入框开着时数字键是打字（搜索框、筛选框都一样），先 `Esc` 退出输入再切。
  「在线歌单」里不含「我喜欢」（它是菜单第一项，只读）；`3` 进搜索屏（进去即可打字），`/` 留给「筛当前
  列表」——两者互不干扰，搜出来的结果也能再筛。
- **队列**：`Enter` 那一刻的列表成为队列（换歌单、重新搜索都不影响它），之后 `a`/`A` 往队列里加，
  `u` 里能跳播、删除、清空。一首播完按模式决定下一首；顺序模式播到队尾会停下并在状态行说明。
  队列里没版权的歌（实测常见）会自动跳过，连着 3 首都不可播就停下报错。**队列内容与各屏选中
  位置退出即丢**（不落盘）。

全局热键（`[hotkeys]`）里关于桌面歌词的有两条：`lyrics = "ctrl+shift+d"` 开 / 关那个窗口
（**关掉是把窗口拆了**，不是藏起来；再按一次重新建。开不开记在 `desktop-lyrics.json`，重启保持），
`lock = "ctrl+shift+l"` 切它的锁定 / 解锁（桌面上那个窗口见「功能」，锁定态默认就是**点不着**的
那一种）。两条只在主界面生效——登录屏没有可控制的东西，按了当没按。

## 配置

`~/.config/canto/config.toml`（首次运行自动生成）：

```toml
# 音质下限：从这一档往下找，这一档没有就退到更低的一档（播放与下载都用它）
#   128    MP3 128k   约 3–5 MB/首   ← 默认
#   320    MP3 320k   约 8–12 MB/首
#   flac   FLAC       约 25–35 MB/首
#   hires  Hi-Res     单曲可到 ~150 MB
quality = "128"

# 下载目录（`d` 键落盘的歌曲），支持 `~`
download_dir = "/Users/you/Music/canto"

# 歌词目录（下载时另存的 .lrc，跟歌曲分开放），支持 `~`
lyrics_dir = "/Users/you/Music/canto-lyrics"

# 播放缓存上限（MB，0 = 关掉）；缓存在 ~/.cache/canto，按「最久没听的先删」维护
cache_mb = 1024

# 播放历史最多保留多少条
history_limit = 500

# 状态行右侧那条通知存活多少秒（0 = 不自动消失，只被下一条顶掉）
notice_seconds = 4

# 全局快捷键：canto 在后台（没聚焦）时也能用这几个键控制播放。
# 注意：注册期间这些组合**别的程序收不到**（系统级注册的固有代价）。
# 写法：修饰键在前、最后一个是要按的键；修饰键可写 ctrl / alt / shift / win
# （win = super = cmd），键名如 space / up / down / left / f5 / a；
# 别用媒体键名（macOS 上那要走系统授权）。空字符串 = 这个动作不注册。
[hotkeys]
play_pause = "ctrl+shift+space"
next = "ctrl+shift+right"
prev = "ctrl+shift+left"
volume_up = "ctrl+shift+up"
volume_down = "ctrl+shift+down"
lock = "ctrl+shift+l"
lyrics = "ctrl+shift+d"

# 桌面歌词（Windows / macOS）：播放时在桌面之上浮一条歌词，默认点不着；
# 全局热键 lyrics（默认 ctrl+shift+d）开 / 关这个窗口，lock 解锁后能拖动
# ——开关与位置都是状态，记在 desktop-lyrics.json 里。
# 颜色写 #RRGGBB，opacity 是 0-100。
# font 是字体面：默认那串是 Windows 的中文字体，macOS 上认不出来会自动回退系统字体
# （想指定就写 macOS 上有的名字，如 "PingFang SC"）。
[desktop_lyrics]
font = "Microsoft YaHei UI"
font_size = 28
color = "#FFFFFF"
outline = "#000000"
next_color = "#9E9E9E"
opacity = 90
show_translation = true
hide_when_paused = false
```

字段缺了就用默认值（老配置文件不用动就能继续用）；**整个文件写坏了也能启动**（用默认值，并在
状态行给一句提示、细节写进 `canto.log`）。界面上不提供设置项——改配置就是开这个文件改，改完重启。

## 文件

```
~/.config/canto/          # 数据目录（XDG 习惯，三平台同一套路径）
  session.json         # cookie jar（= 账号凭据：别提交、别分享）
  config.toml          # 音质 / 下载目录 / 歌词目录 / 缓存上限 / 历史上限
  history.json         # 播放历史（最近 N 条）
  local_playlists.json # 本地歌单（自己建的；条目只存 mid + 标题/歌手快照，所以文件不在了也还在列表里）
  canto.log            # 日志（--log 控制级别）
  canto.lock           # 单例锁（内容只是持有者 pid）
  login-qr.png         # 二维码落盘的一份（o 用它调查看器，也可以自己用相册扫）
  desktop-lyrics.json  # 桌面歌词的开关与窗口位置（可随时删，删了回默认：开着 + 底部居中）

~/.cache/canto/           # 播放缓存（可随时丢；跟数据目录分开，备份不用带它）
  <mid>.<档位>.<ext>   # 完整听过的歌，重听直接读它
  lyrics/<mid>.lrc     # 歌词缓存（空文件 = 这首确实没有歌词）

<下载目录>/                # `d` 键落盘的歌曲（只放音频）
<歌词目录>/                # 同一次下载的 .lrc / .trans.lrc（跟歌曲分开放）
```

目录位置改过：老版本在 macOS 的 `~/Library/Application Support/canto`。首次启动时会把
**整个目录一次性搬过来**（会话、配置、历史、日志一起走，登录态不用重扫，只在「新目录还不存在」
时动手）。

## 已知限制

- **「我喜欢」只读**：界面里没有收藏 / 取消收藏的入口（原来的 `f` 已删）。移除那条路本来就
  走不通（把歌从「我喜欢」移出恒回 `80105`）；加入即使服务端回成功，也反映不到界面上——写完
  不会重拉「在线收藏」那一屏。两种情况都只能去官方客户端处理。普通歌单的加 / 删正常。
- **全局快捷键只有 Windows / macOS 真注册**：Linux（含 Wayland）启动时只说一句「此平台暂不支持
  全局热键」，其余功能照常。另外**注册期间那几个组合是被 canto 独占的**（系统级注册的固有代价），
  别的程序收不到——包括你在别的编辑器里想按同一个组合。
- **`[hotkeys]` 写坏了只影响那一条**：键名不认识、或漏了修饰键（比如 `play_pause = "space"`，
  那等于让 canto 抢走全局空格），启动时会给一句点名字段的警告并跳过它；`""` = 明确禁用。
  两条动作写了同一个组合时，后注册的那条失败并在状态行说明，其余照常可用。修饰键写 `win`
  也能用（内部归一成 crate 认的 `super`）；**别把动作绑到媒体键名上**——macOS 上那要走系统授权。
- **播放缓存不是离线方案**：缓存只收「从头顺序听完」的歌（中途跳过、往回拖过的不进缓存），所以
  「第一次听某首歌」仍然完全依赖网络。**要离线听，用本地曲库（`5`）**：那份东西在你自己磁盘上，
  跟网络无关。
- **本地曲目用路径当身份**：文件改名 / 移动 = 变成另一首（历史与（阶段二的）歌单条目会显示
  「已丢失」）。这是「不做内容哈希」换来的简单。
- **本地曲库只收现有解码器能解的格式**（mp3 / flac / m4a-AAC / ogg-Vorbis / wav）：白名单外的
  音频（opus / ape / wma / ALAC 等）不进列表，扫描完在状态行说一句跳过了几首。
- **未登录时 QQ 三屏仍然画在首页**（进去只给一句「需要登录：按 L」）：刻意的发现性取舍；
  「历史」屏未登录时只列本地条目。
- **列表里那一列（格式 + 档位 + 体积）按配置的下限算**：配置成 128 就列 `MP3 128k 4.4MB`，免得
  以为它要下无损。**本地已经有那份时先报那一份**（缓存 > 下载目录 > 曲库，依次取第一个命中的）；
  都没有才按配置下限预估。**起播也按这个顺序取源**（`●`/`↓` 那两行放的就是列表报的那一份），
  播放条那一格会写明来源（在线 / 缓存 / 下载 / 曲库）与实际在放那份的大小。
- **播放条那一格的来源是「实际打开的那一份」**：缓存文件解不开、退回网络的那次写「在线」；
  曲库（`[library] dirs` 扫出来的曲目，那屏按 `Enter` 播的）写「曲库」——**同一份文件从 `5`
  那屏播写「曲库」、从在线列表里播写「下载」**（两条链路不同；`[library]` 没配时曲库就是下载目录）。
- **搜索接口不返回 hires 大小**，所以搜索结果的档位标签与体积可能低估（不影响取流）。
- **历史屏：老条目没有时长/专辑/音质/体积**——记录里没存（只有 mid / 标题 / 歌手，够重播：取流只认
  mid）。升级后**新播的**条目在起播时就把时长、专辑与各档位体积一起落盘，所以那几列是真的；
  老条目显示 `--:--` / `—`，从别的列表再播一次它就补齐了。
- **专辑那一列只在装得下时出现**：表头是 `标题 歌手 专辑 时长 音质 体积 缓存 下载`（历史屏多一个
  `备注`），宽度按窗口让位——60 列（最小窗口）下专辑自己就出局，跟没加它之前一模一样；没有
  album tag 的本地文件、升级前的老历史条目写 `—`。
- **本地歌单里的歌靠 mid 查当前曲库补齐**时长/专辑/容器/大小：条目快照本身只存 mid / 标题 / 歌手
  （所以文件被移走也还在）。文件真被移走（列表里标「（已丢失）」）那一行才退到 `--:--` / `—`。
- **`↓` 按文件名认**：认定规则是「下载目录里有 `歌手 - 标题.<扩展名>`」，所以同歌手同标题的两首
  会互相标上；手工拷进去的文件也算已下载。
- **`↓` 的档位只到容器**：文件名里没有码率信息，mp3 一律写 `MP3`（不区分 128/320），体积取磁盘上
  那份的真实大小。想知道是哪一档，看有没有 `●`（缓存那份知道档位）——**播放条也一样**：放下载
  那份时读不出档位，只报体积。
- **`●`/`↓` 那两行起播的是磁盘上那份**：`●` 优先于 `↓`，两者都没有才去线上取流。所以**手工拷进
  同名文件**（`歌手 - 标题.<扩展名>`）也会被当成已下载、直接放它——它要是不对，放出来的就是它。
- **同一个 `歌手 - 标题` 有多份时取容器更高的那份**（hi-res > flac > mp3），体积报那一份的。
- **列表的表头会吃掉一行**：内容区矮于 6 行时不画表头（把那一行还给数据）；另外中文表头压着
  帮助浮层时，浮层左上角那一格可能被中文字的后半格盖掉——终端里「宽字符后面那一格画不上」的
  固有行为（ratatui 的缓冲约定），只影响那一格。
- **同一首歌在同一列表里出现两次，两行都会标 `♪`**：标记按 mid 比对，比按标题字符串准，但重复
  出现的同一首无法区分。
- 「会话已失效」的判定码还没等来一次真实的会话过期去核对。
- **桌面歌词只有 Windows / macOS 有**：Linux（含 Wayland）不建窗口，`[desktop_lyrics]` 整段不生效，
  界面与播放照常。
- **`[desktop_lyrics] enabled` 已移除**：开关改用全局热键 `lyrics`（默认 `ctrl+shift+d`），开不开
  记在 `desktop-lyrics.json` 里（跟窗口位置同一个文件，可随时删）。老配置里写着那个键的话，启动
  会给一句点名警告，并且**在状态文件还没记过开关时拿它当一次启动初值**（所以设了 `enabled = false`
  的人升级后不会突然冒出个窗口）；之后按热键就是唯一入口。
- **热键「关」是真把窗口拆掉**（Windows 收线程与窗口、macOS 把 panel 关掉），不是藏起来——所以关着
  的时候这块功能零成本；代价是刚拆的那一下窗口是重新建的，锁定态回到默认（锁定、点不着）、
  拖动过的位置留着。
- **macOS 上每次「关」会在进程里留下一个已下屏的窗口对象**（AppKit / 窗口服务会记住这个窗口，
  实测约 75 KB/次）：一直连按开关很多次才会看出来，正常用（一天开关几次）可以不管。
- **macOS 的解锁态在「有歌词」时没有额外视觉标记**：Windows 解锁时会描一圈白线，macOS 只有没内容
  时才显示「拖动我（再按一次 ctrl+shift+l 锁定）」那句话。觉得不够显眼就说一声，补一圈边框不难。
- **桌面歌词只认主屏**：多显示器下不会跟着跑到别的那块屏；换过显示器 / 分辨率导致窗口落在屏外
  时，下次启动会把它夹回主屏内（留一圈边距），免得「再也找不到」。
- **桌面歌词压不过全屏独占应用**（游戏之类）：Windows 的既有边界，那个时候歌词会被它盖住。

每一条的来龙去脉（含接口实测记录）在 `docs/design.md`。

## 开发

```bash
cargo test                  # 键位、队列、历史、config、缓存、渲染冒烟…
cargo clippy --all-targets
```

（`Engine::silent`），CI 机器没有声卡也跑得动。发布走 `.github/workflows/release.yml`：打一个跟
`Cargo.toml` 版本一致的 tag（例如 `v0.1.1`）就会编三份产物并挂到 GitHub Release 上。
